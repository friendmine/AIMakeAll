# 实验 25 · 换语料后，怎样判定训练改动有价值

给两层四头的字节模型读中文技术课程。若把 ASCII 目标的交叉熵权重加倍，模型能否更好地预测夹在中文里的英文和符号？先约定选型指标，再分别看中文字节和整个留出集付出的代价。

## 重做实验

1. 使用 Python 3.10+、CPU 版 PyTorch、Verilator、C++ 和带 newlib/libm 的 RV32IM 裸机 GCC。在仓库根目录运行 `make lab25`。可单独用 `python3 labs/25-model-study/snapshot.py` 从固定 Git 提交验证语料来源。[仓库许可](../../LICENSE) · [数据划分与选型契约](contract.json)
2. 使用快照内的 28 篇课程文档，整篇按 20/4/4 分为训练、验证、测试。抽取中文段落并全局去除完全相同的段落。每种方法分别从种子 251、252、253 初始化模型，每 100 步留存同一训练批次的加权目标和未加权 NLL。每对种子的初值、窗口和采样顺序相同，各训练 600 步、460,800 个目标字节。权重加倍应用于全部 ASCII 字节，包括空格、数字和标点。
3. 在验证集先筛选整体字节困惑度不超基线均值 5% 的方法，再按三个种子的平均 ASCII 负对数似然（NLL，越低越好）选型。在测试集对全部 24,642 个目标字节作最后一次比较，并按 ASCII、UTF-8 首字节和续字节拆开计分。
4. 对预先指定的种子 251 导出九个 INT8 投影，保留浮点归一化与注意力。让同一 RV32 固件在 PicoRV32 的 CPU、NPU 两条路径处理“时序”，对照宿主量化参考。

| 方法 | 验证 ASCII NLL | 验证整体 PPL | 三个种子各自的测试 PPL | 测试 ASCII / 首字节 / 续字节平均 NLL |
| --- | ---: | ---: | --- | --- |
| 等权基线 | 3.372 | 12.730 | 12.447 / 12.640 / 12.671 | 3.194 / 2.066 / 2.612 |
| ASCII 权重 ×2 | **3.146** | 13.130 | 12.844 / 12.842 / 13.050 | **2.974** / 2.173 / 2.654 |

预设目标选中加权方法。它在三个种子的测试集上均提高了整体困惑度。种子 251 在同一测试位置上有 676 个首选字节由错变对、836 个由对变错。在《ARCHITECTURE》第 812 字节，前文以 `Py` 结尾，真实的 `t` 取代了基线预测的空格；同一文档第 41 字节，基线猜中的 `S` 被加权模型预测成空格。偏移从零开始。三个种子的结果适用于这份教学语料。[逐种子指标、相同位置的预测与样例](verified-run.json)

**部署验收。** 量化包的测试 PPL 为 12.855。两条整机路径均生成 `E6 9C 89`（“有”），三步的 768 个输出分数按位相同，与独立宿主计算最大绝对误差为 0.000000954，门槛为 0.0001。CPU 设备命令数为零，NPU 每步均提交命令。检查点、模型包、原始串口与报告写入 `build/model-study/`。[训练、评估与部署程序](study.py)

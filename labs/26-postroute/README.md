# 实验 26 · 把胜出的 NPU 送去布线

实验 24 的短中长请求选中“四行 Q/K/V 调度 + 权重整字读取”。其中软件调度在 PicoRV32 上运行。本实验把**流式 4×4 阵列、MMIO 控制器和 DMA**组成的 `projection_mmio` 单独作为硬件顶层，比较原电路与整字读取版。CPU、片外 RAM 和软件不计入这块版图的面积。

## 工具、输入与复现

在含 Yosys 和 OpenROAD 的 LibreLane 3 环境中准备 `sky130A/sky130_fd_sc_hd`。本机使用 LibreLane 3.0.17、OpenROAD 提交 `dcf36133`、Yosys 0.62、open_pdks 提交 `8afc8346`。归档中提供三个 Liberty 库、SDC 与各项 RTL 输入的 SHA-256。本次每版的单轮工作目录约 1.3 GiB。[本机工具记录](../../docs/LOCAL_EDA_ENVIRONMENT.md) · [布线与汇总程序](route.py) · [时序约束](timing.sdc)

1. 仓库根目录运行 `make lab26`，或通过 `PDK_ROOT=/path/to/pdks LIBRELANE=/path/to/librelane make lab26` 指定环境。PDK_ROOT 指向包含 `sky130A` 的父目录。命令读取实验 24 的本机选择，缺省时读取归档选择。
2. 两版都用 650 × 650 µm 区域、50 ns 时钟、0.1 ns 时钟不确定度、相同 I/O 延迟和负载。流程依次做综合、布局、时钟树、全局与详细布线、RC 提取，最后做布线后 STA。九个分析角来自三种互连 RC 与三种单元工艺、电压、温度条件的组合。
3. 从 `build/postroute/<方案>/runs/<运行>/` 读取全局布线的逐层利用率与溢出、详细布线错误数、最终网表和九角 STA 的 `max.rpt`、`min.rpt`。运行 `python3 labs/26-postroute/summarize.py` 可从这两次真实运行重新提取下表与路径端点。

## 一次时序失败怎样修复

初次按默认保持修复余量运行，基线最差保持余量 +0.028 ns，整字读取版为 **−0.083 ns**，路径从异步复位输入 `rst_n` 到一个触发器的复位释放检查。时钟周期不变，将两版的布局后 / 全局布线后保持修复余量分别从 0.10 / 0.05 ns 调至 0.40 / 0.45 ns，再从头运行。初版可用 `python3 labs/26-postroute/route.py word_dma --default-margin` 重现；要恢复正式对照，再运行 `make lab26`。[初版实测](initial-margin.json) · [修正后的九角报告](verified-run.json)

| 布线后指标，同一组修复参数 | 基线 | 整字读取 |
| --- | ---: | ---: |
| 标准单元面积（µm²） | 154,546 | 155,713 |
| 详细布线线长（µm） | 462,216 | 466,840 |

| 详细路由器报告的违规数 | 0 | 0 |
| 九角最差建立余量（ns） | +28.523 | +29.064 |
| 九角最差保持余量（ns） | +0.347 | +0.385 |
| 最大电容 / 最大转换时间违规计数 | 50 / 1,850 | 50 / 1,714 |

整字读取版多用 1,167 µm² 标准单元面积（+0.76%），总线长多 4,624 µm（+1.00%）。最差建立路径在最大 RC、慢速、100°C、1.60 V 角，从 `array4.activation[16]` 的寄存器发出，到 `array4.acc[11][30]` 的寄存器结束。最差保持路径从 `write_en` 输入发出。结合实验 24，可以用 0.239% 的整机周期收益和这些物理成本决定是否保留电路改动。[整机与诊断数据](../24-design-challenge/README.md)

**验收边界。** 两版在规定时钟下九角建立与保持余量均非负，全局溢出和详细路由器错误均为零。慢角仍有电容和转换时间超限，后续电气收敛需要逐网调整驱动和缓冲并重新提取。以上是 NPU 数字子模块的布线与 STA 证据；流片签核还需要完整芯片、电源完整性以及独立的版图规则和版图网表一致性检查。

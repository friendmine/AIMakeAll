# 独立毕业题 · 在预算内交付一次模型推理

**状态：待独立试读。** 适合已经跑过实验 17、能读懂一条 DMA 请求、能解释验证集与测试集用途的学习者。先完成本页的预登记，再打开参考解。正式考核由另一人提供最终确认输入，作者演示使用的六条公开提示用于练习。

## 发题与预登记

1. 评审人提供模型包上限、可写内存上限、质量指标和短中长三条开发提示。双方约定输入用 UTF-8 字节计长、每次生成三个字节、相同负载一票。评审人单独保存三条未公布的确认提示，至少一条提示长度不能被四整除。
2. 学习者记录提交号、机器、工具版本、预算及各阶段周期预测。写下预计最耗时的阶段、最可能有效的一项软件改变与一项 RTL 改变，冻结第一版预测。
3. 准备固定权重、相同输入的四组对照。给出一种会违反预算或降低质量的备选设计，说明何时会改变选择。如果改训练方法，预先约定训练预算、验证集选择规则和留出数据。
4. 在开发集完成选择并记录提交号和时间后，评审人才交付确认集。在第一份契约中填入新预算、开发提示，并把 `confirmation` 留作空数组。运行下方第一条命令，把 `selection.json` 提交给评审人。待确认提示揭晓后，只在同一契约中填入确认数组，再执行第二条。程序重新核对开发约束、模型、固件和两版 RTL 仿真器的摘要，只测基线和已选设计。修改候选实现时同步登记并检查它的数值、协议与计量口径。
5. 评审人另给一份带布局、形状或尺度错误的小型教学张量。先给出第一处分歧的算子、下标、期望值和观察值，再修复并用原失败样本回归。记录是否需要提示和卡住的位置。

先用 `make lab24` 的工具和依赖准备好课程模型与仿真器。下面的路径指向学习者自己保存的契约。

```sh
python3 labs/24-design-challenge/challenge.py --contract build/reader-contract.json --output build/reader24 --select-only
python3 labs/24-design-challenge/challenge.py --contract build/reader-contract.json --output build/reader24-confirm --confirm-from build/reader24/selection.json
```

## 评分与提交

| 交付 | 分值 | 评审人核对 |
| --- | ---: | --- |
| 需求、数据与事前预测 | 15 | 可复核提交时间，开发与确认样本分开，资源和质量约束可计算 |
| 数字电路 | 25 | 可综合的改动、尾块与未对齐输入、背压与复位、一次读写计数预测及独立整数参考 |
| 模型研发 | 20 | 在另一语料上提交等预算基线与消融，三个配对种子，验证集选择，测试集按同一位置给出改善与退化例 |
| 模型推理 | 25 | 实际 RV32 固件、每请求 768 项误差 ≤ 0.0001、逐字节选择一致；首步、后两步、完整请求分别计时，报告 KV 和栈 |
| 取舍、诊断与复现 | 15 | 给出落选方案；从读事务、CPU 分段与布线后路径解释结论；复现并修复收到的新故障 |

建议以 80/100 分为及格线。独立通过还须三项能力各取得至少一半分值，满足预先约定的数值和资源门槛，并定位新故障。若没有可行方案，提交各候选超出哪项约束、可复现的证据和新的需求建议；按论证质量评分。

# 实验 24 · 为三种提示长度选择推理设计

独立学习者先取[无答案考题与评分表](exam.md)。以下是作者参考解。本实验沿用实验 10 的宽度 48 模型、实验 15 的九个量化投影和实验 18 的流式 4×4 阵列，给同一 PicoRV32 两种可独立开关的改动。

- **软件改动**把提示阶段第一个 Transformer 块的 Q/K/V 投影按最多四行一组提交；后续层、注意力和 KV 仍按因果顺序执行。每次解码只处理新来的一个字节。
- **电路改动**让 DMA 在权重四列且地址对齐时，用一次 32 位读取得到四个 INT8 权重。尾列和未对齐地址走逐字节读取。
- **选择规则**为开发集三条完整请求的周期之和最小。各请求生成三个字节，模型包 ≤ 75,000 B，KV 预留 ≤ 49,152 B，含栈的链接可写区 ≤ 98,304 B，验证集字节 PPL ≤ 8。确认集只运行基线与已选方案。[事前预测、输入与门槛](contract.json)

## 重做与排查

在仓库根目录执行 `make lab24`。需要 CPU 版 PyTorch、Verilator、C++、带 newlib/libm 的 RV32IM 裸机 GCC。首先训练并导出权重，随后构建两种电路和两种调度固件。单查 DMA 边界可运行 `make word-dma-test`。所有原始输入、串口、按拍记录的 MMIO 写、传输计数与报告在 `build/design-challenge/`。

1. 在 `score/` 里找到三条开发提示（4、12、24 字节），对照首步 `U/E` 和两个后续步。首步包括提示处理与选出首字节；完整请求从首步开始到第三步结束，包括步间开销，随后的串口打印和固件启动另计。
2. 用 `mmio` 的六个配置字段、启动与清除核对每条命令，再读 `counters` 里的 DMA 读写数。例如组合方案的 24 字节开发提示首步，有 144 条四行命令、2,368 条一行命令。遇到不一致，先用独立 DMA 检查定位布局、尾块或背压。
3. `profile/` 来自**另编的诊断固件**。每步细分为配置、设备忙、完成到清除、驱动其余部分、投影中的 CPU 工作、归一化、注意力与 KV、GELU、其余步骤。各项相加覆盖该诊断步；候选名次只用 `score/` 的未插桩固件。
4. 冻结开发集选择后，再比较另三条等长提示，并在 5 字节提示上单查四行分组后的尾行。这里的确认提示公开，正式独立考核由评审人另出。

24 字节开发提示的首步 DMA 读事务少了 63.1%，三条确认请求合计省下 562,172 拍（0.239%）。诊断基线的长提示首步主要花在 CPU 的注意力与 KV（45.7%）和 GELU（28.6%），设备忙仅占 0.48%。缩短到四字节时，GELU 占 42.5%，注意力与 KV 占 13.2%。下一次优化可以从这两种负载各自的主要成本提出假设。

**验收记录。** 每条请求对照宿主参考的 768 个分数和三个选中字节，候选间所有分数按位一致。验证集 PPL 7.762，模型包 74,240 B。两种固件都预留 49,152 B KV，三个确认提示实际有效 KV 峰值分别为 3,072、7,168、13,312 B。基线 / 组合的链接可写区是 62,144 / 63,872 B（均含 4,096 B 预留栈）；仿真中跟踪实际栈指针，确认集实用栈峰值为 1,840 / 2,016 B。各路径还核验每块的 MMIO 顺序与精确 DMA 事务数。192 个硬件定向用例覆盖行列 1–4、归约 1/13/32、四种地址偏移及周期性背压，另在读事务中途复位并重新提交。[整机与分段报告](verified-run.json) · [DMA 验收记录](verified-dma.json)

# 实验 07 · 让同一份固件切换模型和 Q/K/V 后端

实验 04 在宽度 32 模型上测得，处理提示词时 45.73% 的整步周期花在 RV32 软件浮点 Q/K/V 投影上。本实验把归一化后的 16 维输入一次投影成 48 维 Q、K、V，保留 FP32 注意力、KV 缓存和输出投影。**默认样本首次加载 A 到首符号从 8,057,092 拍降至 5,939,153 拍；在相同 INT8 精度下，阵列比 RV32 再省 86,635 拍。** 三条路径的前馈升维均由同一块 4×4 H1 阵列执行。[实验 04 的瓶颈定位](../04-rv32-performance/README.md) · [实验 06 的包与缓存](../06-model-switch/README.md)

## 复现

在仓库根目录运行。依赖为 make、Python 3.10+、CPU PyTorch、Verilator、C++ 编译器及带 newlib、objcopy、nm 的 RV32IM/ILP32 裸机 GCC。

```sh
make fused-qkv
make fused-qkv GEN_SAMPLE=1
```

结果写入 `build/fused-qkv/sample-编号/`。每个样本只构建一份 ELF。从复位起，每条路径分别运行一次相同的固件和输入文件，在一次启动中依序完成 A → 异址 A → B → A、六个坏包、原址 A 恢复请求。A 为宽度 32，B 为 24。测试台提供只读后端选择值；选择一次，持续到该次启动结束。三个路径目录分别保存原始串口、带周期的 MMIO 写、DMA/阵列事件和缓存写轨迹。[默认样本报告](verified-sample-0.json) · [样本 1 报告](verified-sample-1.json)

以下命令从新的构建目录重训两个检查点、重建两个仿真器并复测。

```sh
make fused-qkv PROJ_BUILD=build/repro07/models GEN_BUILD=build/repro07/soc QKV_BUILD=build/repro07/results
```

## 模型包、量化与逐项验证

1. **从实验 06 的字节开始。** 先重建 v1 包，核对两个完整模型和 v1 包的归档 SHA-256。沿用 20 B 包头及原始载荷，版本号升为 2，尾部追加 1 个 Q/K/V 输入尺度、48 个通道尺度（FP32）和 768 B 行主序 INT8 权重，共增 964 B。A、B 包分别为 **10,568 B、9,864 B**。原始 FP32 权重供对照路径使用。实验 06 的入口继续使用 v1；实验 07 的三条路径均校验完整 v2 包。[导出与独立参考](oracle.py) · [固件](qkv.c)
2. **固定量化配方。** 单独使用实验 02 训练集前 32 条序列，在注意力输入归一化后按最大绝对值校准一个激活尺度。每个输出通道独立量化权重，使用对称 INT8、最近偶数舍入、范围 [−127, 127]、INT32 累加。结果乘两个尺度再加 FP32 偏置。沿用该模型已有的前馈尺度。两个模型独立校准。
3. **用完整留出集查质量。** 每个模型分别用 64 条序列、512 个预测位置计算困惑度，再从提示自主生成三个符号和 EOS。对双投影量化模型，还把两个投影都实际送入独立 H1 阵列仿真器并将结果接回模型。每个宽度的 5,632 个输出分数及 64 条生成序列均与宿主整数参考一致。
4. **用整机查实际数据路径。** 同一 PicoRV32 固件另在两个留出提示上逐请求核对运行。每次有效请求检查 384 个 Q/K/V 浮点值、实际缓存的 256 个 K/V 值、A 的 256 或 B 的 192 个前馈 INT32、44 个 logits 和 4 个符号。两条整数量化路径还核对 384 个 Q/K/V INT32。检查器验证 K/V 缓存与对应投影值逐位相同，并对照宿主参考和两条 INT8 路径的整份数值记录。[串口、总线与计时检查](qkv_checks.py)

## 同一台 PicoRV32 的请求周期

从请求进入、读取包描述符前开始用 `rdcycle` 计时。到首符号包括校验全包、选择或重建缓存、处理 5 个提示位置和选出第一个符号；整请求一直量到选出 EOS。三个后续生成步分别从处理一个新符号量到选出下一个符号。首尾计时包含步骤间控制开销。串口数值转储位于请求计时之外。以下每格均为 **到首符号 / 到 EOS**，单位为拍。默认提示的四次主请求均生成 `2 → 5 → 6 → EOS`。

| 请求 | RV32 浮点 Q/K/V | RV32 INT8 Q/K/V | NPU INT8 Q/K/V |
| --- | ---: | ---: | ---: |
| 首次 A，冷启动 | 8,057,092 / 14,095,617 | 6,025,788 / 10,841,084 | **5,939,153 / 10,697,074** |
| 异址 A，内容命中 | 8,115,597 / 14,154,122 | 6,084,293 / 10,899,589 | **5,978,389 / 10,736,310** |
| 切到 B，重建 | 7,640,515 / 12,979,879 | 5,611,014 / 9,730,752 | **5,524,379 / 9,586,742** |
| 切回 A，重建 | 8,057,092 / 14,095,617 | 6,025,788 / 10,841,084 | **5,939,153 / 10,697,074** |
| 坏包后的原址 A，命中 | 8,044,220 / 14,082,745 | 6,012,916 / 10,828,212 | **5,907,012 / 10,664,933** |

| 模型及生成步 | RV32 浮点 | RV32 INT8 | NPU INT8 |
| --- | ---: | ---: | ---: |
| A，输入 2 生成 5 | 1,913,350 | 1,507,091 | 1,487,966 |
| A，输入 5 生成 6 | 1,954,380 | 1,544,653 | 1,525,528 |
| A，输入 6 生成 EOS | 2,170,426 | 1,763,183 | 1,744,058 |
| B，输入 2 生成 5 | 1,768,622 | 1,361,650 | 1,342,525 |
| B，输入 5 生成 6 | 1,722,503 | 1,315,556 | 1,296,431 |
| B，输入 6 生成 EOS | 1,847,870 | 1,442,163 | 1,423,038 |

默认 A 的冷首符号相对浮点少用 **26.29%**，完整请求少用 **24.11%**，后三个生成步合计少用 **21.21%**。相对已量化的 RV32，NPU 冷首符号再省 **86,635 拍**，每个后续符号再省 **19,125 拍**，整请求再省 **144,010 拍**。样本 1 生成 `0 → 4 → 1 → EOS`，NPU 冷 A 的首符号和整请求分别为 5,891,555 和 10,719,463 拍。以上周期适用于当前符号模型、软件浮点、PicoRV32 与每七拍一次 DMA 等待的 RTL 仿真配置。

## 为什么缓存命中仍可能更慢？

NPU 路径在四次主请求中写入 Q/K/V 缓存 **768、0、768、768 B**，写入前馈缓存 **512、0、384、512 B**。两条 RV32 Q/K/V 路径仅准备前馈缓存，Q/K/V 缓存写入始终为零。三条路径使用同一 ELF，预留相同的 1,280 B 权重缓存区。宽度 24 的 NPU 请求实际使用其中 1,152 B。驱动实际读取的每个块地址和 CPU 写入的每个字节均已检查。

每次 A 请求的全包校验都花 **2,467,865 拍**。校验后，NPU 冷 A 的缓存选择与重建花 **32,246 拍**。第二次 A 位于另一地址，固件逐字节比较包内容，虽无缓存改写，选择仍花 **71,482 拍**，热首符号因此比冷首符号多 **39,236 拍**。原址 A 恢复时可凭只读地址确认身份，选择仅花 **105 拍**。三种情形的 A 提示计算本身均为 3,438,937 拍。

一个 5 行提示按 4+1 行提交，融合 Q/K/V 有 48 个输出列，每次生成分别新增 **24、12、12、12 条** Q/K/V 命令。加上前馈后，NPU 路径 A 各步为 40、20、20、20 条，B 为 36、18、18、18 条。RV32 两条对照路径仅有前馈命令，A 为 16、8、8、8 条，B 为 12、6、6、6 条。

## 拒绝坏包与验收标准

依次提交当前 A 的权重位翻转、截短 B、非法宽度、前馈通道 NaN、Q/K/V 输入尺度为零、Q/K/V 末通道 NaN。尺度用例均重算 CRC32，分别触发尺度错误。三个后端对每个坏包都返回预期错误码；请求窗口内设备命令、寄存器写入、DMA 握手、两段缓存写入均为零。六次拒绝后代次保持 3，原址 A 正常命中并逐位复现第一次 A 的输出。

| 交付物 | 验收标准 |
| --- | --- |
| 模型包与质量报告 | 原模型和 v1 包摘要符合实验 06；v2 包含独立的 Q/K/V 尺度与权重。每宽度 64/64 整序列正确，双投影量化困惑度相对仅前馈 INT8 增幅 ≤1%、相对全 FP32 增幅 ≤10%。全留出阵列重放的分数与整数参考逐位一致。 |
| 三路径整机数值 | 每个有效请求的整数和符号逐项一致，浮点与各自参考的绝对误差 ≤0.0001。两条 INT8 路径分数与中间值逐位一致，实际 K/V 等于对应投影。两个提示实测的最大 logit 绝对误差低于 0.000003。 |
| 缓存与异常 | 总线核实各路径的写入量、字节布局、代次 1/1/2/3、有效 DMA 地址和命令次序。坏包必须在提交前拒绝，设备、DMA、缓存均为零活动，恢复请求命中原缓存。 |
| 性能和复现 | 同一 ELF、同一包与序列分别交付冷、异址热、切换及原址恢复的首符号、后续每步和完整周期；把包校验和选择开销单列。更换提示复验，空目录重训重编后核对默认报告。 |
| 个人迁移 | 任选留出样本 2–63，事先预测异址 A 和原址 A 的权重写入与设备命令，再对照校验、选择、计算三段，解释首符号和整请求各自的差异。 |

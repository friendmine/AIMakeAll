# 实验 03 · 用同一份 RISC-V 固件追踪一次生成

给模型五个符号 `开始 2 5 6 分隔`。它先给出 2，再把刚选出的 2 送回模型，继续生成 5、6 和结束符。本实验让同一个 RV32 程序分别在 QEMU 和 PicoRV32 数字电路上完成这四步。你可以从第一个输出整数一路追到最后一个 token，也可以在两条路径出现分歧时定位第一条有误的设备命令。

复用[实验 01 的设备 ABI](../../specs/npu-v0.md)和[实验 02](../02-trained-projection/README.md)的宽度 32 检查点。实验使用 H1 分库阵列，隐藏维度 16，词表 11，最大上下文 8。训练只在宿主进行。

## 运行

在仓库根目录执行。需要 Python（本机 3.11.7）、CPU PyTorch（实测 2.14.1）、支持 RV32IM/ILP32 的裸机 GCC 及配套 objcopy、newlib 数学库和 libnosys、Verilator、C++ 编译器和 make。使用项目的[QEMU 9.2.4 教学构建](../../simulator/qemu-v0/README.md)，保持构建的内存区域写跟踪可用。PicoRV32 源码已随仓库提供。

```sh
make generation                     # 留出样本 0，两台机器运行同一个 ELF 的程序内容
make generation GEN_SAMPLE=1        # 更换留出提示，重新导出并核对这一对运行
make generation-synth               # 可选，Yosys 对 MMIO 控制器及阵列做通用综合
```

默认读取 `build/projection/copy-32.pt`。首次运行缺少检查点时，make 用实验 02 的原训练配方在 CPU 上重建。可用 `GEN_CHECKPOINT` 指定已有检查点，`LINEAR_QEMU` 指定已构建的教学 QEMU。运行器核验任务、宽度、步数、种子、冻结张量摘要及投影权重、尺度与偏置，然后记录整个模型的参数摘要。新环境可用 `make generation-rtl` 先单独编译电路。newlib 某些发行版会提示文件系统桩函数不可用，裸机通过 UART 和测试结束寄存器输出。

## A · 先核验一层真实投影

1. [导出器](run.py)把完整模型参数、INT8 权重、尺度、偏置和提示词写入固件头文件。标准答案和参考输出保留在宿主。交叉编译一次，QEMU 加载 ELF，RTL 的行为 RAM 从同一 ELF 经 objcopy 生成的字节映像启动。两台机器入口均为 `0x80000000`。
2. [客体程序](generate.c)计算注意力和归一化，将投影输入量化。5×16 的激活与 32×16 的权重形成 5×32 个输出。按四行四列分块，一共 16 条命令。客体把各块的权重从 W[输出,输入] 打包为连续的 B[K,N]。
3. [共享驱动](../../runtime/npu_v0.h)写 A/B/C 地址和 M/N/K，执行内存屏障，写 START、轮询、检查错误并 CLEAR。QEMU 功能设备与 [PicoRV32 连接的 RTL 控制器](../../hardware/rtl/projection_mmio.sv)使用相同的寄存器地址。RTL 控制器通过行为 RAM 的 DMA 接口读取激活和权重，重排 32 位装载字给真实的 4×4 阵列，逐项写回结果。测试台只实现 RAM、串口、结束信号和计数。
4. 对照第一条成功命令。默认样本的形状是 M=4、N=4、K=16。两种后端的首个 INT32 输出均为 `0xffffb96b`（−18069）。每块都检查打包前后字节摘要及全部整数，覆盖第五行尾块。返回值乘回激活及逐通道权重尺度，加一次偏置。

每次运行先提交两条无效命令。零行数应返回错误 2，输出与输入重叠应返回错误 4。两次均须保留结果哨兵，清除错误之后才能提交第一个正常块。因此原始总线轨迹中的第三个 START 才是模型的第一块。

## B · 把投影结果用回生成

一道前馈升维投影由设备完成，嵌入、因果注意力、KV 缓存、归一化、GELU、降维、词表投影和贪心选择由 RV32 固件执行。每一步计算最后一个有效位置的 11 个 logits，用得分最高的 token 构造下一步输入。单层模型可以只对最后一行继续执行降维和输出头。宿主独立运行同一量化模型，检查每步结果。默认样本的实测如下。

| 当前输入 | 分块命令 | INT32 输出 | 设备从系统 RAM 读 / 写 | 选择的 token |
| --- | ---: | ---: | ---: | ---: |
| 开始、2、5、6、分隔 | 16 | 160 | 1664 / 640 B | 2 |
| 刚生成的 2 | 8 | 32 | 640 / 128 B | 5 |
| 刚生成的 5 | 8 | 32 | 640 / 128 B | 6 |
| 刚生成的 6 | 8 | 32 | 640 / 128 B | 10（结束） |

系统 RAM 每次 DMA 读传一个有效字节，写回传一个 32 位整数。局部阵列仍以四字节字装载，尾部无效通道由控制器补零。这解释了实验 02 提示词投影的 2048 B 局部读取与此处 1664 B 系统输入读取为何不同。

## C · 查阅交付物并验收

每个样本保存在 `build/generation/sample-编号/`。仓库另附[默认样本实测报告](verified-run.json)及[实际串口记录](sample-0.uart)，可直接查阅。

| 交付物 | 检查什么 | 通过条件 |
| --- | --- | --- |
| `model.h`、`generation.elf`、`generation.bin`、`report.json` | 完整模型、固件和加载映像的 SHA-256 | 两条路径共用一次导出和编译。更换样本时模型摘要相同 |
| `qemu-mmio.log` 与 `rtl-mmio.txt` | 在两个实际设备窗口观察寄存器写入，检查顺序、地址、维度、START 与 CLEAR | 各有 336 次写入，覆盖 40 条模型命令和 2 条负例的完整写序列 |
| `qemu.uart` 与 `rtl.uart` | S 标记生成步，I/H 是块坐标与形状，X/W 是输入摘要，P 是整数，L 是浮点分数的原位编码，T 是 token | 两份串口记录逐字节相同。全部 256 个整数匹配独立参考，44 个 logits 有限且逐项绝对误差 ≤ 0.0001，4 个生成符号含 EOS 与参考和留出标签一致 |
| `rtl-counters.txt` | S 到 T 的时钟沿、每块接受命令到最后结果写回的周期、DMA 读写和等待 | 每块有效读取数为 (M+N)K 字节，写回 M×N 个整字。每步的最后一块完成后才会发出 token |
| 迁移与排错 | 换一个未演示的 `GEN_SAMPLE`（0–63），先预测命令数和字节数，再定位第一处整数或寄存器偏差 | 各步形状与预测一致，输出由新提示驱动。检查器对坏整数给出步骤、块和输出坐标，对坏写序列给出命令编号 |

在默认提示词阶段，RTL 从 S 标记到 T 标记共 5,721,480 拍，各块的“阵列接收命令至本块最后写回”合计 2,814 拍。前者包含无浮点单元的 CPU、软件数学库、打包、轮询和详细串口日志。后者包含流式装载与 DMA 等待。当前配置使用两个逻辑 RAM 访问口，DMA 每七拍暂停一拍。QEMU 用于比较数值与设备访问顺序。同负载的纯 CPU 周期与 NPU 周期见[实验 04 同机对照](../04-rv32-performance/README.md)。

RTL 实现的单命令范围为 1–4 行、1–4 列、K=1–32，使用 32 MiB 行为 RAM，支持本实验的对齐 32 位 MMIO 访问。这是 v0 的共同微块子集。Ibex 集成、全部 v0 形状、真实外存时序与自然语言大模型另有验收。[项目里程碑](../../docs/ROADMAP.md)

# 实验 23 · 用真实 QEMU Type 3 窗口放置权重与 KV

启动 q35、单个 CXL 主桥、根端口与 256 MiB 易失 Type 3。读取已分配的组件 BAR 和固定窗口，编程 HDM decoder，确认提交并读写探针。把同一模型的权重与 KV 分别置于本地 RAM 或扩展窗口；宿主执行算术，逐步从 QEMU 地址读权重、读已有 KV、追加新 KV。

## 运行

从仓库根目录执行 `make lab23`。QEMU 9.2.4 x86 系统构建、CPU PyTorch。此实验使用 qtest 驱动物理地址事务。 [环境与完整复现顺序](../../docs/EXPERIMENTS_09_23.md#复现环境)

## 交付与验收

四种放置必须生成相同的四个字节，全部 1,024 个 logits 与参考逐位相等。逐项列出本地与扩展容量、首次装载和请求读写量；在本地数据预算 80 KiB 下判断可行性，并检查分配边界。

四种放置都续写了 “the ”。全本地需要 83,968 B，超预算 2,048 B。只把 KV 放入 CXL 时，本地用 74,240 B，请求跨窗读写 35,840 B；只外置权重时为 296,960 B。80 KiB 约束只计算权重与有效 KV 的驻留字节，宿主计算临时量和系统内存单列在实验范围之外。带宽扫描给出搬运时间下界，QEMU 功能模型提供地址与数值证据。

[本机已验证的报告](verified-run.json) · 新运行的报告位于 `build/cxl-placement/report.json`。

## 迁移练习

在固定 16 GB/s 的假设下，估算两种可行方案的传输下界；解释在哪种复用策略下结论可能改变。

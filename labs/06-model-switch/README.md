# 实验 06 · 同一份固件切换两个模型

实验 05 的固件只服务一个常驻模型。现在把实验 02 独立训练的两个检查点分别导出为 A（前馈宽度 32）和 B（宽度 24）。PicoRV32 只启动一次，按 **A → A → B → A** 连续生成。第二次 A 来自另一个地址，第四次 A 回到原地址。两次都要读 A，为什么只有第二次能省掉打包？

## 运行

在仓库根目录运行。环境为 make、Python 3.10+、CPU PyTorch、Verilator、C++ 编译器和带 newlib、objcopy、nm 的 RV32IM/ILP32 裸机 GCC。检查点缺失时按实验 02 的配方训练。

```sh
make model-switch
make model-switch GEN_SAMPLE=1
```

每个样本生成一份 `generation.elf`、固件映像、两个合法模型包（`A.amp` 和 `B.amp`）、独立的请求输入 `requests.bin`，以及 `build/model-switch/sample-编号/report.json` 和四份原始轨迹。两个样本使用逐字节相同的固件。要从空目录验证训练、构建和运行，可执行以下命令。[默认报告](verified-sample-0.json) · [留出样本 1 报告](verified-sample-1.json)

```sh
make model-switch PROJ_BUILD=build/repro06/models GEN_BUILD=build/repro06/soc SWITCH_BUILD=build/repro06/results
```

## 先预测缓存写入，再查总线

1. **导出。** 对每个检查点重新校准升维投影，核对实验 02 已发布的 INT8 权重、激活尺度、每通道权重尺度和偏置。其余算子使用该检查点的 FP32 参数。A 包为 9,604 B，B 包为 8,900 B。模型和提示均从仿真只读输入区交付给固件。[导出器](packages.py) · [实验 02 基准](../02-trained-projection/README.md)
2. **加载。** RV32 先检查请求边界、格式版本、宽度、精确长度和载荷 CRC32，再检查所有浮点值有限且量化尺度为正。全部通过后才选择模型。包头为五个小端 32 位字，分别记录魔数（字节 `AMP1`）、版本 1、前馈宽度、载荷字节数和载荷 CRC32。载荷依次为激活尺度、逐通道尺度、固定形状 FP32 张量、升维偏置、降维权重和行主序 INT8 升维权重。张量次序与尺寸见代码。CRC32 用于检出数据损坏。[固件加载器](model.h)
3. **选择权重。** 单槽缓存最多容纳 512 B。相同只读包或逐字节相同的副本复用旧布局；其他通过校验的包按 `[输出块][深度 16][通道 4]` 重排。B 只重写前 384 B，设备的六个块地址均落在这段有效区间。切回 A，八个块全部重建。每个请求的 KV 位置从零开始。[固件](switch.c)
4. **验证生成。** 使用同一套驱动把升维投影交给 4×4 阵列。宿主从各自原始检查点独立计算参考，按提示词阶段和三个后续生成步逐块核对。两个模型都会复述同一提示，首个投影整数和最终分数能区分实际执行的是哪一个。[逐项检查](check_switch.py) · [NPU 驱动](../../runtime/npu_v0.h)

## 实测

默认提示为 `开始 2 5 6 分隔`。表中权重写入量来自 CPU 内存总线，命令数来自设备写入与 RTL 完成事件。每个有效请求均输出 `2 → 5 → 6 → EOS`。

| 请求 | 缓存动作 | 缓存代次 | 写入缓存 | NPU 命令 | 首个 INT32 | 核对整数 / logits |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 首次 A | 建立 8 个块 | 1 | 512 B | 40 | −18,069 | 256 / 44 |
| 再次 A（异址副本） | 命中 | 1 | 0 B | 40 | −18,069 | 256 / 44 |
| 切至 B | 重建 6 个块 | 2 | 384 B | 30 | −2,510 | 192 / 44 |
| 切回 A | 重建 8 个块 | 3 | 512 B | 40 | −18,069 | 256 / 44 |

A、B 的激活尺度分别为 `0.03197935596` 和 `0.03049632348`，对应 FP32 位模式 `3d02fcc9` 和 `3cf9d36d`。四个请求逐项核对 **124 个尺度值、960 个投影整数、176 个 logits、16 个生成符号**。三次 A 的全部分数逐位一致，B 的分数与自己的独立参考吻合。默认样本的 logits 最大绝对误差为 **0.0000028611**。留出样本 1 生成 `0 → 4 → 1 → EOS`，最大误差为 **0.0000019074**，复现了相同的缓存与命令序列。

### 坏包在设备提交前被拒绝

四个主请求结束后，在同一次启动中依次提交下列输入。最后再提交合法 A，单独检查失败后的恢复。

| 输入 | 固件观测 | 设备命令 / 寄存器写入 | DMA 读 / 写 | 缓存写入 |
| --- | --- | ---: | ---: | ---: |
| 当前模型 A 的一个权重字节翻转 | CRC32 不符，错误 3 | 0 / 0 | 0 / 0 B | 0 B |
| B 截短一个字节 | 长度不符，错误 1 | 0 / 0 | 0 / 0 B | 0 B |
| 包头声明宽度 28 | 宽度不支持，错误 2 | 0 / 0 | 0 / 0 B | 0 B |
| B 最后一个通道尺度改为 NaN，并重新计算 CRC32 | 尺度无效，错误 4 | 0 / 0 | 0 / 0 B | 0 B |
| 恢复对照 A | 命中第 3 代，生成至 EOS | 40 / 320 | 3,584 / 1,024 B | 0 B |

要复查零命令，可在 `rtl-counters.txt` 找到第五至第八个请求的 `R` 和 `Z`。这两行记录请求起止周期和 DMA 累计握手数。每对之间无 tile 完成，累计握手数相等；按同一周期窗口查 `rtl-mmio.txt` 与 `cache-stores.txt`，均无记录。默认样本在第一个坏包开始前已累计 14,400 次 DMA 握手，直到第四个坏包结束仍为 14,400；恢复 A 后增加至 18,240。报告的 `rtl_window` 字段保留每个窗口的周期与计数器读数。原始数值在 `rtl.uart` 中，可按顺序查看 `X/W` 尺度、`P` 整数、`L` 分数和 `T` 符号。每份报告保存四条轨迹的 SHA-256。

## 验收标准

| 交付物 | 通过条件 |
| --- | --- |
| 固件与两个模型包 | 两个检查点通过实验 02 的固定投影核对，记录完整模型与输入包摘要。同一次启动完成四个主请求，换留出提示仍使用相同的固件映像。 |
| 单槽缓存和设备访问 | 四个请求的实际写入量依次为 512、0、384、512 B。每次重建逐字节等于独立转置，且在首条描述符之前完成。逐条检查设备权重地址、形状、START、CLEAR 和 DMA 量。 |
| 数值与生成 | 每请求按 FP32 位模式核对一个激活尺度及所有通道尺度，INT32 和 token 全部相等，全部 logits 有限且对各自参考绝对误差 ≤ 0.0001。A 切回后的分数逐位复现首次 A。 |
| 拒绝与恢复 | 四个坏包分别命中预期错误，零设备命令、零设备寄存器写入、零 DMA、零缓存写入；缓存代次保持 3。恢复 A 命中并复现首次输出。 |
| 个人迁移 | 自选留出样本 2–63，运行前写下四个请求的缓存写入量、设备命令数和尺度数。运行后从总线定位一次命中、一次重建和一次拒绝，并用两个模型的具体中间值解释如何判断切换正确。 |

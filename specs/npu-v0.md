# NPU v0：算子语义与设备 ABI 草案

状态更新于 2026-11-18。Python、C 和单 MAC 的算术已对照。[QEMU v0 功能设备](../simulator/qemu-v0/README.md)已在 RV32 裸机上跑通正常任务，错误/状态/复位覆盖范围见设备检查记录。[实验 03](../labs/03-rv32-generation/README.md)已验证共同微块子集的 MMIO 从机、PicoRV32 与阵列整机生成。该 RTL 单命令支持 M/N 1–4、K 1–32，RAM 范围为 0x80000000–0x81ffffff。驱动负责拆分 M/N。下文的最大维度 256 适用于完整 v0 与 QEMU，其他形状及完整异常语义在 RTL 上单独验收。

## GEMM 语义

`C[M,N] = A[M,K] × B[K,N]`。A、B 为行优先、连续的二进制补码 INT8，取值 -128…127；C 为行优先 INT32。初始累加器为零，不包含 bias、缩放、激活或旧 C 累加。不支持 batch、转置、非连续 stride。M、N、K 必须为正数。

乘积先精确扩展至有符号 32 位，再累加，结果按二进制补码模 2^32 回绕，不饱和。Python 参考允许任意正维度；首版设备限制各维度不超过 256，并进一步要求全部缓冲区落入其配置的有效 RAM。量化运行时应避免溢出，不能把回绕当作误差补偿。

示例：`[[1,-2,3],[4,0,-1]] × [[2,1],[-3,2],[1,-4]] = [[11,-15],[7,8]]`。

## MMIO 寄存器提案

基址由机器内存映射决定。本仓库锁定的 QEMU 教学配置映射到 0x10010000，其他平台需单独分配。窗口至少 4 KiB，仅支持小端、对齐的 32 位寄存器访问。未定义、只读写入或不支持宽度访问应产生总线访问错误。

| 偏移 | 名称 | 语义 |
| --- | --- | --- |
| 0x00 | ABI_VERSION | 只读，v0 编码为 0x00000001 |
| 0x04 | COMMAND | 只写：1 START，2 CLEAR；其余值报命令错误 |
| 0x08 | STATUS | 只读：bit0 BUSY，bit1 DONE，bit2 ERROR |
| 0x0c | ERROR_CODE | 只读：0 无，1 命令，2 形状，3 地址/对齐，4 重叠 |
| 0x10 | A_ADDR | 输入 A 的 32 位 guest 物理地址 |
| 0x14 | B_ADDR | 输入 B 的 32 位 guest 物理地址 |
| 0x18 | C_ADDR | 输出 C 的 32 位 guest 物理地址，4 字节对齐 |
| 0x1c | M | 行数 |
| 0x20 | N | 列数 |
| 0x24 | K | 归约维度 |

START 前检查尺寸、地址加法与字节数溢出、整段读写范围、C 与 A/B 的重叠；A/B 允许互相重叠。失败设置 ERROR，C 保持不变。成功从 IDLE 进入 BUSY，完成后设置 DONE。DONE/ERROR 为终态，CLEAR 后回到 IDLE 并清除错误码；配置寄存器保留。只有 IDLE 可以修改配置或 START；其他状态的寄存器写入产生总线访问错误而不修改正在执行的事务。BUSY 不允许 CLEAR；设备复位可取消事务并清零所有配置与状态。

首版采用轮询，无中断，无虚拟地址转换，无 cache coherence 保证。guest 驱动在提交前和读取结果前使用适当的 I/O/内存屏障；未来引入 cache 时增加缓存维护协议。错误状态、超时、复位和非法访问必须有专门测试。

## 模型量化边界

模型线性层通常是 `Y = X W^T`；导出器负责把权重转换成设备需要的 B[K,N]，不能直接把原始 W[N,K] 当作 B。首版计划使用零点为零的对称 INT8 量化，CPU 处理缩放和 bias。若权重逐输出通道缩放，则 `Y[m,n] ≈ C[m,n] × s_x × s_w[n] + bias[n]`。激活 scale 的校准/动态选择由运行时负责，并随模型导出记录。

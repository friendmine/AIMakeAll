# Agent 主线（待实现）

已有一个可运行的规则练习。助手引用旧预算，用户可查看两份实际运行报告、纠正引用并决定确认或接管，任务记录操作数与终态。自训练模型驱动的工具循环按下文独立实现。[人机协作练习](../labs/01-linear257/README.md)

目标是建立“任务 → 模型决策 → 工具执行 → 观察 → 决策/结束”的可检查循环，推理经统一运行时调用自训练模型。

拟定消息形态：

```json
{"type":"tool_call","name":"calculator","arguments":{"expression":"12 * 7"}}
```

```json
{"type":"final","answer":"结果是 84。"}
```

工具返回单独的 observation，不允许工具内容直接改变执行权限。工具名必须注册、参数必须校验，计算器使用受限语法解析，不能调用 `eval`。首版仅提供计算、限定目录检索和实验结果读取，不执行任意 shell。限制最大步数、单次超时、上下文长度，并记录完整轨迹。

先用规则策略验证循环，再用自训练模型接替决策。两种策略的结果必须分开。非法 JSON、未知工具、参数错误、工具超时、重复调用和达到步数上限，都应有可预测的错误处理。

持久状态与安全按 [STATE-E1–E6](../docs/ENGINEERING_BRIDGES.md) 细化：先建立权限边界与单机任务库，记录身份范围内的请求编号、内容摘要、尝试编号和终态；用同一数据库事务内的模拟副作用验证崩溃恢复，再测试外部已执行但回复丢失的窗口。无法确认时保留“结果未知”，不盲目重做；数据库事务不能自动覆盖外部工具。所有新实验待实现，先使用规则策略、隔离目录与模拟工具，权限由程序执行，审计轨迹须脱敏。

公开独立任务集、正确答案/成功判据、模型配置、成功率、工具调用合法率与总耗时。最终对照相同模型的 CPU 和 NPU 路径，观察计算加速对整个任务的贡献。详见 [M4 验收](../docs/ROADMAP.md)。

[CLA/EMB/SCALE 补全路线](../docs/CHIP_AI_COMPLETENESS.md) 增加有限逻辑、概率推断与经典规划对照，感知/估计/控制的二维仿真，以及服务规模/恢复验收。经典策略成绩不当作 LLM 能力，Agent 高层任务循环不替代实时控制；均为待实施规划。

## ENG04 深化：检索与决策质量

AGQ-E1–E6 归入已有领域 02/09/10/12，连接 AL04/AL06、UDL08、LLMFS07、ENG04 和 STATE-E1–E6，全部待实现。它们评估“找对依据、选对动作、完成任务”，复用已有权限与恢复约束；不新增 Agent 框架或一级领域。先用原创本地资料、规则策略与模拟工具，后接自训练模型。

| 子实验 | 知识与前置 | 实验产物 | 验收要求 |
| --- | --- | --- | --- |
| AGQ-E1 任务与相关性标注 | ENG02、UDL08；查询意图、证据、任务成功条件、数据泄漏 | 固定小资料集及至少 30 个留出任务，含单步/多步、无答案、冲突与越权情形；标注文档/段落关联和期望动作 | 按文档/模板族划分开发与测试；测试答案不进入索引或提示，资料中的正常事实可以检索；标注分歧可追溯 |
| AGQ-E2 检索与排序 | AL04/AL06；倒排索引、词项权重、Top-k、相关性评价 | 先对照词项计数与 TF-IDF/BM25 中一种明确实现，再按需引入向量或重排候选 | 固定分词、分块、k 和并列规则；手算小排名核验 Precision/Recall@k、MRR；分级标签再用 nDCG；记录延迟与索引容量 |
| AGQ-E3 上下文与依据 | LLMFS02/07；token 预算、去重、来源/版本、冲突与无答案 | 固定模型/模板，比较无检索、检索和去重/预算选择；保存引用段落与输入上下文 | 引用指向真实且支持回答的证据；统计正确回答、无依据断言与适当拒答，不能以引用数量替代质量；冲突来源不被静默合并 |
| AGQ-E4 工具选择与终止 | STATE-E1/E4、AL07；动作前置条件、参数、预算、重复状态 | 规则策略选择检索/计算/结果读取，加入补充信息、拒绝与结束状态；构造缺参数/工具失败/循环任务 | 明确动作与终态；格式合法、工具执行正确、任务成功分别计分；无依据不得假报成功，达到预算有确定终态 |
| AGQ-E5 多步计划与修正 | AGQ-E4、STATE-E2/E6；子目标依赖、观察反馈与局部重规划 | 同一工具环境比较直接策略、固定分解与观察驱动调整；规则与模型版本分别记录 | 保存结构化子目标/动作/观察/结果；以实际执行和终态验收，长解释不算成功；遵守相同总步数/token/工具预算，副作用仅在模拟环境 |
| AGQ-E6 消融与端到端质量 | AGQ-E1–E5、SIM07、PERF-E6；错误归因、配对比较、质量/成本权衡 | 固定留出集比较检索/上下文/策略配置，接模型后再比较 CPU 与 NPU | 报告任务成功率、调用合法率、拒答/超时/失败、token/工具次数和延迟；失败任务不从分母剔除，质量与性能同时保留 |

检索评价先固定粒度：文档级指标须对重复 chunk 去重，段落级指标使用段落标注。Recall@k 的分母依赖明确的相关集合；无相关项的查询单独评价无答案识别，不计算零分母召回。nDCG 明示增益/折扣及 IDCG=0 的处理，不能把未标注项自动视为已确认不相关。查询改写、重排和 k 的选择只使用开发集。

AGQ-E3 对不同上下文策略固定 tokenizer、模型权重和生成设置，实际输入长度/截断规则可追溯。精确答案任务用程序评分，开放回答用预先定义的人工标准与复核；外部评判模型为可选诊断，不是核心依赖。注入文本和检索内容仍属不可信输入，不能绕过 STATE 的授权与路径限制。

AGQ-E6 可用人工指定正确证据作诊断对照，以区分检索失败与回答失败，但单独标记，不能计入实际检索系统成绩。多步任务允许多条有效动作路径，以目标状态和约束验收，不强制复刻一条标准轨迹。置信区间或重复实验注明独立单位；小样本不据此声称通用能力。错误分类至少含检索遗漏、证据选择、计算/回答、工具选择/参数、执行故障、权限拒绝和错误终止，按任务预期区分正确拒绝与失败。

参考 [信息检索评价](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-ranked-retrieval-results-1.html) 与 [ReAct 原论文](https://arxiv.org/abs/2210.03629) 的动作/观察组织思路。只链接原始资料并设计自己的实验，不复制数据集或预设本项目小模型能达到论文效果。

## 网络服务扩展（待实现）

按 [NET03–NET05](../docs/NETWORKING_FOUNDATIONS.md) 把本地调用扩展为远程推理与受限工具服务：先 CPU/规则策略验证协议，再接模型和已验收的 NPU 后端。加入请求编号、deadline、身份与权限检查、有界队列、重试和结果查询；对模拟副作用做断连/重启测试，不承诺仅凭重试实现恰好一次执行。远端返回内容仍是 observation，不能改变本地权限。

网络延迟、排队、模型计算、工具耗时和总任务耗时分别记录；远程 NPU 使用情况必须由服务端运行时轨迹证明。阶段安排见 [S2](../docs/ROADMAP.md)，不依赖 CXL 或 RDMA。

## 共用 FIFO 的建模规则

SIM03 复用 DD03 的接口与复位规格。周期模型每个上升沿先读取旧状态和输入，以旧 `ready/valid` 计算传输，再统一提交下一状态；测试台按同一采样约定观察 RTL。复位沿取消旧数据并进入新 epoch，接收与发送均为零。

纯队列模型只对已经接受的事务给出顺序与内容，不自行猜测设备何时 ready；周期模型另验证 ready/valid 和占用，避免用 DUT 给出的接收事件掩盖 DUT 的握手错误。满时允许读但不接受同沿新写，空时写入最早在后续沿被读取。

最小事件记录建议包含模型/规格版本、运行编号、epoch、整数时间及单位、事件序号、请求编号、输入/输出传输、数据和状态摘要。离线比较器定位第一处分歧，并区分输入不一致、模型假设差异、协议错误与数值错误。

## 从“跑出结果”到“结论可信”

每份报告包含：要回答的问题 → 模型用途与简化 → 参数及来源 → 实验输入 → 校验依据 → 结果与误差 → 可适用范围 → 尚未覆盖内容。状态分别标注“未校验”“与手算/参考一致”“与 RTL 对照”“有实测校准”；不把它们压成一个百分比。

校验先采用手算轨迹和守恒关系，例如已接收 = 已发送 + 当前占用 + 已取消。再用未参与调参的流量检验。没有物理设备时，仍可以形成条件性的设计比较，但不能给模拟参数套上“真实 PCIe/CXL 性能”的标签。

参数化模型可研究“带宽减半时瓶颈如何改变”，不能只从理想链路速率推导整个模型加速比。深度、批量、并发与带宽变化需保持比较目标清晰；队列不稳定或容量不足时记录拒绝/溢出，不能只统计成功请求。模型偏差也不能由重复运行缩小的统计区间消除。

## 接入项目的顺序

1. SIM01–SIM04 与 DD03/DV01–DV04 共用 FIFO：先功能队列，再周期模型、RTL 与重放。
2. SIM05–SIM07 迁移到单 Linear：共同输入 → Python/C → 分块计划 → QEMU/RTL；量化质量由 ENG01 检查，周期/成本与假设由本课程检查。
3. 网络使用明确服务时间/到达过程做排队实验；PCIe 使用事务与搬运模型；CXL 使用容量、访问局部性与延迟/带宽范围。各自不暗示完整 PHY 或一致性实现。
4. SIM08 实时联仿是后续扩展；首先用保存的向量和轨迹离线对照，不让联仿基础设施阻塞主线。

# OSTEP 操作系统原理与项目实践

更新：2026-11-17。参考 Remzi H. Arpaci-Dusseau 与 Andrea C. Arpaci-Dusseau 的 [Operating Systems: Three Easy Pieces](https://pages.cs.wisc.edu/~remzi/OSTEP/)，当前官网标识为 1.10。按虚拟化、并发、持久化组织主线，同时纳入分布式与安全主题。`OS01–OS12` 是本项目模块编号，非原书章号。**当前为知识体系和实验设计，尚未实现这些实验或 Linux NPU 驱动。**

## 与 CSAPP 和 LFS 的分工

CSAPP 从程序执行和系统接口建立基础；OSTEP 进一步解释系统内部的机制与策略；LFS 将工具链、用户态和内核组装成可启动系统。三者连接为：理解原理 → 编写小实验 → 构建系统 → 接入设备与应用。

OSTEP 的虚拟化主题包含 CPU 和地址空间虚拟化，不只是虚拟机。其日志结构文件系统的缩写 LFS，也不等于本项目引用的 Linux From Scratch。

## 知识地图与原创实验

参考章段按作者官网目录标识；对话、总结章用于回顾，不单独设置编程任务。以下验收均为本项目设计。

| 模块 / 参考范围 | 学习重点 | 项目实验 | 验收证据 |
| --- | --- | --- | --- |
| OS01 / 引言与进程，1–6 章 | 进程、受限直接执行、系统调用与上下文 | 运行并回收 C 子进程，记录异常退出 | 父子状态和退出码可解释；无僵尸进程；与 CPU trap 区分 |
| OS02 / 调度，7–11 章 | 策略、响应/周转、公平性、多核调度 | 离散事件模拟推理请求的 FIFO 与时间片调度 | 已知小轨迹可手算对照；明确服务时间假设，不把模拟结果当实际 OS 性能 |
| OS03 / 地址空间，13–16、18–20 章 | 地址转换、分段、分页、页表与 TLB | 小型地址翻译器及 TLB 模拟 | 非法访问拒绝；缺页/TLB miss 区分；页内偏移和权限正确 |
| OS04 / 分配与内存策略，14、17、21–24 章 | 空闲空间、换页、替换策略与工作集 | 对齐 arena 和简单页替换模拟 | 测峰值、碎片和复用；明确模型 KV cache 不等于 OS 页缓存 |
| OS05 / 线程与锁，26–29 章 | 共享状态、原子性、锁与并发数据结构 | 为 AL02 队列增加同步，制造并修复竞争 | 任务不丢不重；锁保护范围明确；压力测试配合可重现竞争用例 |
| OS06 / 同步与事件，30–34 章 | 条件变量、信号量、死锁、事件式并发 | 有界生产者/消费者和取消协议 | 等待条件循环检查；取消唤醒等待者；关闭流程不会永久阻塞 |
| OS07 / I/O 设备，第 36 章 | 轮询、中断、DMA、设备与驱动分工 | 从 NPU 轮询协议追踪请求和完成事件 | 明确 MMIO、内存可见性和设备错误；首版仍按现有 ABI 轮询 |
| OS08 / 存储与文件系统，37–41、44 章 | 存储介质、RAID、文件目录、文件系统布局 | 用普通文件模拟小型块设备和目录索引 | 文件写入/读取/删除一致；元数据边界正确；仅使用实验镜像 |
| OS09 / 持久化正确性，42–43、45–46 章 | 崩溃一致性、日志、校验与损坏检测 | 为 checkpoint/Agent 轨迹设计提交协议并注入中断 | 启动恢复得到有效旧版或新版，拒绝不完整文件；说明持久化假设 |
| OS10 / 分布式扩展，48–51 章 | 远程调用、失败、网络文件系统与一致性 | 模拟工具服务断连、重试、重复请求 | 给请求编号，定义幂等范围；不假定重试带来恰好一次执行 |
| OS11 / 安全扩展，53–57 章 | 身份、访问控制、保护边界与安全通信基础 | 限定模型/工具目录和服务账户，验证越权请求 | 正常请求可用，越权输入被拒绝；不自创密码算法或绕过系统权限 |
| OS12 / 附录及项目补充 | 虚拟机、监视器、系统实验方法；Linux 驱动实践 | 在独立 Linux guest 中研究 NPU 驱动的申请、提交、完成与释放 | 用户地址/guest 物理地址分开；退出与超时回收资源；驱动属于后续自研补充 |

章段与主题来源：[作者目录、作业及项目入口](https://pages.cs.wisc.edu/~remzi/OSTEP/)。具体实验并非官方作业移植，Linux NPU 接口也不是书中现成实现。

## 与项目各层的连接

| 项目任务 | 优先模块 | 实施约束 |
| --- | --- | --- |
| 裸机 NPU 轮询与模拟器 | OS07，加 CS08/CS09 | 不引入默认线程、页表或 Linux 系统调用 |
| C 推理内存与任务队列 | OS04–OS06，AL02/AL06 | 先静态单请求；共享权重与请求私有 KV 状态分别管理 |
| RV64 Linux 与 LFS | OS01–OS09、OS12 | Linux 平台独立于 Ibex 裸机，驱动需设备描述及合适内核配置 |
| Agent 工具服务 | OS01、OS05/OS06、OS09–OS11 | 子进程生命周期、持久状态、取消与幂等均可观察 |

跨平台实践从可移植 C 和模拟程序开始；Linux 专用接口在独立 Linux 环境执行。macOS POSIX 实验、x86-64 LFS 和 RV64 guest 分别记录环境，不以一个平台通过代表全部通过。

## 推荐顺序与验收

本轮在原模块内补深三个连接：[ARCH-E3–E5](ARCHITECTURE.md) 对应 OS03–OS07 的 Cache/地址转换区别、可见性与一致性模型；[SW-E4/E5](SYSTEMATIC_VERIFICATION.md) 对应资源生命周期和跨环境复现；[STATE-E1–E6](ENGINEERING_BRIDGES.md) 展开 OS09–OS11 的任务事务、崩溃恢复、未知结果、授权与审计。它们均是待实现子实验，不新增一级课程；先用软件模型/本地任务库，Linux 专用路径另验。

先做 OS01 进程生命周期和 OS04 arena；接着 OS05/OS06 队列；做模型文件和任务状态时加入 OS09；待 Linux 扩展启动后再做 OS12 驱动。OS02/OS03 的机制模拟可并行学习，OS10/OS11 随服务扩展推进。

每个实验交付：机制与策略的区分、状态图、实现、故障用例、资源释放记录和运行平台。并发测试通过是证据之一，不声称穷尽所有交错；必要时补不变量、工具检查或形式化分析。

作者官网希望学习者链接章节而非复制镜像。本仓库只保存原创映射与实验计划；书籍、作业和示例源码按各自声明核验，不把免费阅读等同于仓库 MIT 授权。

## 实时系统的专题连接

[RT 实时系统](CHIP_AI_COMPLETENESS.md#rt-实时系统) 接 OS02 与 OS05/OS06：先单核 RM/EDF 和响应分析，再用同一锁轨迹比较优先级反转/继承，最后把控制与非抢占推理任务分层。三个节点均待实现；调度/锁/错期证据在离散事件模型中验收，真实 RTOS 或 Linux 平台另验。它是本项目补充课程，不声称 OSTEP 已覆盖全部实时理论；平均/p95 性能不替代硬时限保证。

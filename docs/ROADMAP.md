# 路线与里程碑

目标是建立一套能从数学参考结果追溯到硬件、模型和应用的学习资料。按验收门槛推进，不用尚未测量的速度或未训练的模型作为成果。

总览见 [全景规划图](PROJECT_MAP.md)。[CSAPP 基础模块](CSAPP_FOUNDATIONS.md) 贯穿四阶段：M1 重点为数值、指令、处理器与存储；M2 为链接、异常和地址空间；M3 为精度、性能与内存/I/O；M4 为进程、网络与并发。全书知识已纳入规划，新增基础实验尚未完成。

## M1：RISC-V + 教学 NPU

1. 固定 Ibex 上游提交，保留许可证；先用 RV32IMC 裸机完成 UART 输出、内存读写和中断实验。
2. 从单 MAC 扩展到 4×4 阵列，加入局部存储、分块和尾块处理；首版仅支持整数 GEMM。
3. 设计简单片上互连、MMIO 寄存器和有界内存访问；随后再引入 DMA。
4. 用相同随机向量比较 Python、C、RTL 输出；覆盖复位、忙状态、错误状态和地址越界。

结合 ENG03 增加计算/搬运成本、阵列利用率、协议性质和 SoC 故障用例；工具和外部 EDA 案例已有记录，不计为本 SoC 已完成验证。

交付：SoC 结构说明、RTL、裸机驱动、波形和可重复测试。验收：CPU 发起至少一个完整 GEMM，结果逐元素一致；记录周期及资源使用。FPGA 是后续可选扩展，不作为学习门槛。

物理实现扩展可复用外部 ASIC 实验室的 LibreLane / OpenROAD / SKY130；先迁移一个轻量案例及完整锁文件/补丁，再接入 NPU。普通器件 16×8 SRAM 仅为教学宏，须待 RC/PVT 验收并解决容量与工艺版本衔接后再用于系统集成。

## M2：QEMU 与软件运行时

1. 固定 QEMU 版本，运行原生 RISC-V 裸机示例。
2. 实现 AIMakeAll 专用机器或明确修改的板级模型，以及相同 ABI 的 NPU MMIO 设备。
3. 实现参考设备后端和 guest C 驱动；DMA 只能访问允许的 guest RAM，先校验整段访问再计算。
4. 用 M1 的向量和同一驱动完成对照；加入超时、错误和复位测试。
5. 最后加入可选宿主机优化后端，分别记录功能正确性和端到端耗时。

运行时增加执行计划加载与解释路线，连接 AL07 的依赖顺序、AC08 的缓冲区规划和 OS04 的内存生命周期；先同步单请求，后续再做队列与并发。

验收：真实 guest 程序读写虚拟 NPU、获得结果并处理错误。必须记录 QEMU 提交、机器、CPU、guest 构建参数及宿主机配置。Python 参考函数不能充当 QEMU 集成完成的证据。

### M2 扩展：LFS 与 RV64 Linux

按 [LFS 阶段 LF1–LF5](LFS_FOUNDATIONS.md) 推进：独立 Linux 构建环境 → 工具链与临时系统 → 基础 LFS 冷启动 → RV64 Linux 适配 → NPU 驱动与 AI 服务。先在 x86-64 基准环境理解构建流程，再对 RV64 固件、内核、rootfs 和用户态 ABI 单独验收。

该扩展不改变 M1/M2 的 Ibex RV32 裸机目标。只有 Linux 启动、设备驱动、GEMM 对照、模型推理和服务生命周期分别通过，才能宣称 Linux AI 系统接通；当前仅完成文档规划。

## M3：从零 LLM 与加速器部署

理论基础：[UDL 学习路线](UDL_FOUNDATIONS.md)。先用小网络理解损失、梯度、优化和泛化，再进入残差与 Transformer；量化、导出及硬件算子映射为项目补充实验。

参考线：[MiniMind 学习与接入](MINIMIND_INTEGRATION.md)。本项目自写小模型主线保留，MiniMind 用于完整训练流程对照和后续部署；已固定审阅提交，训练、量化和设备接入尚未实施。

1. 用来源清晰的小型文本集完成 tokenizer、数据切分、bigram 基线。
2. 自己实现 decoder-only Transformer：embedding、causal attention、MLP、残差和归一化；允许用 PyTorch 自动求导。
3. 从随机权重训练约 1M–10M 参数的教学模型；保存随机种子、配置、训练曲线和独立验证集结果。
4. 完成 FP32 推理、KV cache、INT8 线性层量化、权重导出和 C 运行时。
5. 将线性层接入 M2 的 GEMM；Softmax、归一化与非线性先留 CPU。比较量化前后困惑度、logits 误差及生成样例。

由 [AI 编译课程](AI_COMPILATION.md) 实现模型到设备的转换：先固定形状 Linear，完成布局与量化、K 分块部分和、缓冲区与执行计划，再扩展到模型线性层。ENG01 检查数值误差，ENG02 建立去重/划分、数据版本与训练恢复证据，ENG03 验证性能来源。

验收：可从公开配方重建权重；验证损失优于 bigram；量化相对困惑度增幅的初始目标不超过 10%，超标就记录失败并调整量化方案。必须实测 prefill 与 decode，报告搬运开销和 CPU 回退比例。

## M4：建立 Agent

结合 UDL08/UDL21 建立独立评估和能力边界；UDL19 的强化学习作为后续扩展，不作为首版工具调用的前置条件。

结合 MiniMind 的对话模板与工具调用示例学习协议，优先自有受限工具 SFT 与任务评测；其示例模拟数据和额外奖励模型须明确标记，Agent RL 为后续扩展。

1. 定义结构化工具调用与有步数上限的执行循环，先用规则策略验证协议。
2. 从自有任务模板生成合法训练样本，单独划分模板外测试集。
3. 训练小模型输出工具调用；不合格输出交给校验层拒绝或重试，不能执行任意生成代码。
4. 提供限定目录文档检索、计算器、实验结果查询三个工具。
5. 经模型运行时调用 NPU 后端，对照 CPU 路径完成相同任务集。

ENG04 增加本地索引/Top-k、检索独立评估、请求编号、持久状态、幂等重试和故障恢复。与 AL04/AL06、OS06/OS09–OS11 结合，先用模拟副作用验证，再接实际工具。

验收：固定 30 个以上独立任务，公开成功率、调用合法率、超时率、模型耗时与总耗时。规则策略与模型策略结果必须分开；教学小模型若尚不能可靠调用工具，应保留失败记录，不宣称通用 Agent 已完成。

## 下一次开发的具体范围

硬件继续推进 M1 的“4×4 INT8 阵列与 Python 随机对照”，随后再集成 CPU。软件并行实现 AL07 计算图检查、C 整数参考及固定形状 Linear 的计划解释器；按 [单线性层贯通实验](AI_COMPILATION.md) 接 QEMU/RTL，再扩大到完整 LLM。

推进门槛：图检查和量化参考 → C 计划执行与数值对照 → 设备 GEMM 与分块 → 单线性层端到端报告 → 模型集成。首个演示可使用原创固定权重，不等待完整模型训练；OSTEP 小实验和 LFS 系统扩展按需求并行。首次引入外部项目时固定不可变提交与许可证，每项实现同时补实验正文。

# 路线与里程碑

目标是建立一套能从数学参考结果追溯到硬件、模型和应用的学习资料。按验收门槛推进，不用尚未测量的速度或未训练的模型作为成果。

默认按 [仿真优先原则](SIMULATION_FIRST.md) 完成全部核心学习验收：数字模块交付可综合 RTL 与仿真/综合证据，协议和系统用软件模型、QEMU/Linux 与虚拟网络。实板、PHY 电气测试和流片为独立可选项。

总览见 [全景规划图](PROJECT_MAP.md)。[CSAPP 基础模块](CSAPP_FOUNDATIONS.md) 贯穿四阶段：M1 重点为数值、指令、处理器与存储；M2 为链接、异常和地址空间；M3 为精度、性能与内存/I/O；M4 为进程、网络与并发。全书知识已纳入规划，新增基础实验尚未完成。

## M1：RISC-V + 教学 NPU

1. 固定 Ibex 上游提交，保留许可证；先用 RV32IMC 裸机完成 UART 输出、内存读写和中断实验。
2. 从单 MAC 扩展到 4×4 阵列，加入局部存储、分块和尾块处理；首版仅支持整数 GEMM。
3. 设计简单片上互连、MMIO 寄存器和有界内存访问；随后再引入 DMA。
4. 用相同随机向量比较 Python、C、RTL 输出；覆盖复位、忙状态、错误状态和地址越界。

结合 ENG03 增加计算/搬运成本、阵列利用率、协议性质和 SoC 故障用例；工具和外部 EDA 案例已有记录，不计为本 SoC 已完成验证。

[ARCH-E1/E2](ARCHITECTURE.md) 随阵列推进：先比较相同 GEMM 的数据流与访问账本，再测局部存储 bank/端口约束下的停顿与利用率。[MATH-E1/E2/E6](UDL_FOUNDATIONS.md) 按需补不变量、矩阵和整数误差；[SW-E1/E5](SYSTEMATIC_VERIFICATION.md) 先建立定义明确的 C 参考和实验环境记录。缓存/一致性模型不阻塞无缓存保证的首版。

DD01–DD05/DD08 补单时钟设计与数据路径，DV01–DV07 补协议/参考/覆盖与工具适用范围内的证明，SIM01–SIM05 对齐模型和 RTL 轨迹。模块交付包含 DD07 的基础综合检查；多时钟和目标库 STA 分别按需求推进。

[MEM-E1/E4](ARCHITECTURE.md) 随 S0 先做事务账本与两来源单存储端口的仲裁，DRAM 调度和小 NoC 作为独立模型后置。[PPA-E1/E2](DIGITAL_DESIGN_TIMING.md) 随小模块建立相同功能/库/约束的面积—时序对照；功耗分析等适用的库与活动证据具备后再验，不阻塞主线功能实现。

交付：SoC 结构说明、RTL、裸机驱动、波形和可重复测试。验收：CPU 发起至少一个完整 GEMM，结果逐元素一致；记录周期及资源使用。FPGA 是后续可选扩展，不作为学习门槛。

物理实现扩展可复用外部 ASIC 实验室的 LibreLane / OpenROAD / SKY130；先迁移一个轻量案例及完整锁文件/补丁，再接入 NPU。普通器件 16×8 SRAM 仅为教学宏，须待 RC/PVT 验收并解决容量与工艺版本衔接后再用于系统集成。

## M2：QEMU 与软件运行时

1. 固定 QEMU 版本，运行原生 RISC-V 裸机示例。
2. 实现 AIMakeAll 专用机器或明确修改的板级模型，以及相同 ABI 的 NPU MMIO 设备。
3. 实现参考设备后端和 guest C 驱动；DMA 只能访问允许的 guest RAM，先校验整段访问再计算。
4. 用 M1 的向量和同一驱动完成对照；加入超时、错误和复位测试。
5. 最后加入可选宿主机优化后端，分别记录功能正确性和端到端耗时。

运行时增加执行计划加载与解释路线，连接 AL07 的依赖顺序、AC08 的缓冲区规划和 OS04 的内存生命周期；先同步单请求，后续再做队列与并发。

接入 [SW-E2–E6](SYSTEMATIC_VERIFICATION.md)：模型包先校验再加载，覆盖坏包、分配失败、设备错误与超时回收，形成固定回归语料；支持的宿主启用程序检测，guest 路径另验。重建环境分别报告功能复现与逐位一致性，不把未执行的平台写成通过。ARCH-E4 的可见性教学模型可并行；真实 Linux DMA API 路径随 S1 独立验证。

[PERF-E1–E4](ENGINEERING_BRIDGES.md) 在 C 正确性之后依次建立基线、分块、SIMD 和线程对照；宿主与 guest 各自声明 ISA/线程支持。G2 先交付 PERF-E1 的可复核计时与输入契约，后续才要求完整优化 CPU 基准。PERF-E5 的异步重叠为独立模型/后端实验，不能更改 v0 同步轮询假设。

SIM01–SIM04 定义设备模型边界、事件次序和重放，DV08 关联 guest 请求与设备轨迹。首版只做共同向量/事务离线对照；SIM08 的 QEMU–RTL 实时联仿另验时钟、事件、共享内存和复位桥接。

验收：真实 guest 程序读写虚拟 NPU、获得结果并处理错误。必须记录 QEMU 提交、机器、CPU、guest 构建参数及宿主机配置。Python 参考函数不能充当 QEMU 集成完成的证据。

### M2 扩展：LFS 与 RV64 Linux

按 [LFS 阶段 LF1–LF5](LFS_FOUNDATIONS.md) 推进：独立 Linux 构建环境 → 工具链与临时系统 → 基础 LFS 冷启动 → RV64 Linux 适配 → NPU 驱动与 AI 服务。先在 x86-64 基准环境理解构建流程，再对 RV64 固件、内核、rootfs 和用户态 ABI 单独验收。

该扩展不改变 M1/M2 的 Ibex RV32 裸机目标。只有 Linux 启动、设备驱动、GEMM 对照、模型推理和服务生命周期分别通过，才能宣称 Linux AI 系统接通；当前仅完成文档规划。

## M3：从零 LLM 与加速器部署

理论基础：[UDL 学习路线](UDL_FOUNDATIONS.md)。先用小网络理解损失、梯度、优化和泛化，再进入残差与 Transformer；量化、导出及硬件算子映射为项目补充实验。

[MATH-E3–E6](UDL_FOUNDATIONS.md) 随小模型开展梯度检查、最小二乘优化、概率/交叉熵与稳定计算；训练前先能解释这些小实验。以 ARCH-E1/E6 和 ENG03 检查分块、容量、带宽上界与实测差异，prefill/decode 各有固定负载；ARCH-E6 的 CXL/NUMA 放置部分等 S3 条件具备后再做。

参考线：[MiniMind 学习与接入](MINIMIND_INTEGRATION.md)。本项目自写小模型主线保留，MiniMind 用于完整训练流程对照和后续部署；已固定审阅提交，训练、量化和设备接入尚未实施。

逐步实现参考：[Build a Large Language Model (From Scratch)](../models/README.md)。先 LLMFS-A/02 的 PyTorch、短序列与标签，再 LLMFS03/04 的注意力和 GPT，随后 LLMFS05 的随机初始化训练/恢复、LLMFS07 的指令微调。分类微调与 LoRA 后置；外部预训练权重只用于独立对照。量化/NPU 和 Agent 状态安全继续按本项目验收，不据书中示例宣称已打通。

1. 用来源清晰的小型文本集完成 tokenizer、数据切分、bigram 基线。
2. 自己实现 decoder-only Transformer：embedding、causal attention、MLP、残差和归一化；允许用 PyTorch 自动求导。
3. 从随机权重训练约 1M–10M 参数的教学模型；保存随机种子、配置、训练曲线和独立验证集结果。
4. 完成 FP32 推理、KV cache、INT8 线性层量化、权重导出和 C 运行时。
5. 将线性层接入 M2 的 GEMM；Softmax、归一化与非线性先留 CPU。比较量化前后困惑度、logits 误差及生成样例。

由 [AI 编译课程](AI_COMPILATION.md) 实现模型到设备的转换：先固定形状 Linear，完成布局与量化、K 分块部分和、缓冲区与执行计划，再扩展到模型线性层。ENG01 检查数值误差，ENG02 建立去重/划分、数据版本与训练恢复证据，ENG03 验证性能来源。

PERF-E6/MEM-E6 汇总单层到模型的计算、搬运、排队和 CPU 回退成本；只有相同精度/负载下的优化 CPU、设备与模型证据齐全后再评价收益。PPA-E6 的面积/能耗权衡保持明确的设计范围；小模块能耗不能直接外推成完整模型或芯片能耗。

验收：可从公开配方重建权重；验证损失优于 bigram；量化相对困惑度增幅的初始目标不超过 10%，超标就记录失败并调整量化方案。必须实测 prefill 与 decode，报告搬运开销和 CPU 回退比例。

## M4：建立 Agent

结合 UDL08/UDL21 建立独立评估和能力边界；UDL19 的强化学习作为后续扩展，不作为首版工具调用的前置条件。

结合 MiniMind 的对话模板与工具调用示例学习协议，优先自有受限工具 SFT 与任务评测；其示例模拟数据和额外奖励模型须明确标记，Agent RL 为后续扩展。

1. 定义结构化工具调用与有步数上限的执行循环，先用规则策略验证协议。
2. 从自有任务模板生成合法训练样本，单独划分模板外测试集。
3. 训练小模型输出工具调用；不合格输出交给校验层拒绝或重试，不能执行任意生成代码。
4. 提供限定目录文档检索、计算器、实验结果查询三个工具。
5. 经模型运行时调用 NPU 后端，对照 CPU 路径完成相同任务集。

ENG04 增加本地索引/Top-k、检索独立评估、请求编号、持久状态、幂等重试和故障恢复。与 AL04/AL06、OS06/OS09–OS11 结合，先用模拟副作用验证，再接实际工具。

[STATE-E1–E6](ENGINEERING_BRIDGES.md) 先用规则 Agent 验证权限、单机持久任务状态、事务内模拟副作用和重启恢复，再加入断连/重复/并发故障，最后接模型。数据库事务仅覆盖事务内操作；外部副作用未确认时保留未知结果并查询/对账。授权、资源限制与审计由程序执行，不交给模型决定。它们可与 M3 并行，不等待 NPU 或模型训练完成。

[AGQ-E1–E6](../agents/README.md) 先以留出任务和标注资料评估检索，再比较上下文、动作选择、终止和多步策略。E1/E2/E4 的规则实验可与 M3 并行；模型成熟后接 E3/E5/E6，分别记录规则与模型结果。固定开发/测试划分和资源预算，不让检索、生成或 NPU 性能的单项改善代替总体任务成功。

验收：固定 30 个以上独立任务，公开成功率、调用合法率、超时率、模型耗时与总耗时。规则策略与模型策略结果必须分开；教学小模型若尚不能可靠调用工具，应保留失败记录，不宣称通用 Agent 已完成。

## 互连、通信与内存系统：S0–S3 扩展阶段

这些阶段沿用 M1–M4 的数值、性能与任务验收规则，不替代原有四条主线。S2 是并行网络路线，编号不表示必须在 S1 之后开始；S3 的 CXL 实验只要求相关 PCI/Linux 内存基础，不等待完整模型或完整 PCIe NPU。

| 阶段 | 前置条件与对应模块 | 实验安排 | 阶段交付与验收 |
| --- | --- | --- | --- |
| S0 片内数据路径 | M1/M2 的矩阵、地址与状态机；IO01 | 完成 MMIO 单请求 GEMM → 总线握手/错误与数据搬运分析；DMA/中断能力后加 | CPU 发起并取回正确矩阵，非法访问与复位有证据；不改变 v0 同步轮询契约 |
| S1 Linux PCI/PCIe | 独立 Linux guest、C/驱动基础；IO02–IO05；IO06 为 RTL 进阶 | EDU 枚举/BAR → DMA → INTx/MSI → 自定义 PCIe NPU → C 运行时 | 驱动资源生命周期与错误回收通过，独立 PCIe ABI、数值对照、后端轨迹与成本报告齐全 |
| S2 网络服务并行 | CSAPP 网络、OSTEP 并发；NET01–NET05 | 回环协议 → 双 guest CPU 服务 → 有界并发/故障 → 模型与 Agent → 可选远程 NPU | 消息边界、超时/重试、身份与权限检查通过；CPU/NPU 结果和后端分开；记录吞吐、尾延迟与任务成功率 |
| S3 CXL 内存进阶 | IO02/IO03、OSTEP 内存原理与 Linux 环境；CX01–CX05 | 独立 q35 guest → 单 Type 3 发现/译码 → region 与可访问内存 → NUMA/放置 → CPU 模型 | 区域可访问、张量读写正确、容量账本及放置证据齐全；功能、参数估算与真实性能分开 |

NET06 优先软件 RDMA/参数模型；IO06 开展 TLP/BAR/NPU 桥 RTL 仿真与综合；CX06 以 guest 拓扑和有限状态一致性模型推进。这些进阶不依赖实物，也不列入首版完成条件。网络另补 NET-H1–H3 的 MAC/FIFO/CRC，CXL 另补 CX-H1/H2 事务与数字子模块。CXL 首个实验不默认支持当前 RV64 平台；RV64 移植与 NPU 直接访问 CXL 内存另做能力与地址验收。

三条课程：[网络与分布式通信](NETWORKING_FOUNDATIONS.md) · [I/O 与 PCIe](PCIE_IO_FOUNDATIONS.md) · [CXL 与异构内存](CXL_MEMORY_FOUNDATIONS.md)。每个模块都列出产物和失败用例；目前未创建虚拟机、驱动或服务，不勾选实验完成。

## 设计、验证与模型可信度：G0–G3 贯通验收

G0–G3 为贯穿 M1–M4/S0–S3 的证据门槛，不增加另一套必须全部学完的前置课程；目前各门槛均待实验验收。三条课程：[数字设计](DIGITAL_DESIGN_TIMING.md) · [系统化验证](SYSTEMATIC_VERIFICATION.md) · [仿真可信度](SIMULATION_CREDIBILITY.md)。

| 门槛 | 内容与模块 | 共同产物 | 进入下一层的依据 |
| --- | --- | --- | --- |
| G0 契约与计划 | DD01、DV01、SIM01；以 DD03 的固定 FIFO 契约起步 | 接口/采样/复位规则、需求矩阵、模型范围与排除项 | 空满、同沿读写、取消和数据稳定规则无歧义，测试与假设有对应关系 |
| G1 同步 FIFO 闭环 | DD02–DD05、DD07 基础综合；DV02–DV07；SIM02–SIM05 | 参考队列、周期模型、RTL、轨迹/波形、覆盖、故障变体与综合报告 | 数据/握手对照正确，错误变体被捕获，关键性质有明确证明状态；未完成的高级检查单列，不能写成通过 |
| G2 单 Linear 闭环 | DD08、DV08、SIM05–SIM07，与 AC/ENG01/ENG03 联动 | 固定输入 → 计划/C → QEMU/RTL 的数值、协议、成本与适用性报告 | 量化质量与整数正确性分别验收；事件可追溯，校验/调参用例分离，不用虚拟墙钟推导硬件加速比 |
| G3 系统与协议扩展 | DV08、SIM06–SIM08；多时钟时加入 DD06/完整时序约束 | NIC/PCIe/CXL/Agent 的层次化测试、故障与模型报告 | 新接口/时钟/平台重新检查假设；协议子集、形式范围及模型未校准部分明确；联仿/实物不是统一前置 |

G1 最先开展固定深度的单时钟 FIFO；异步 FIFO、布局布线后 STA 和实时联合仿真均按实际需求后置。形式工具未就绪时可推进其他层工作，但必须保留未证明状态，不能以动态测试替代形式结论。

## 四项共同交付的阶段安排

### 首批实现范围

四项共同交付先做一个最小版本，不先建设通用平台：

1. 在现有规范和实验文档登记实验 00/FIFO 的契约来源、资产 ID、观察层和预期结果；固定 manifest 字段，补最小合法/故障样例。
2. 为实验 00 采集只读环境信息，填写最小档数值上限，短跑测时间/资源并核对固定结果；复用清单开始 FIFO，后续延伸到 C/Linear。
3. 实现输入哈希核验和最小结果比较/失败重放入口，先覆盖实际可运行的参考与 MAC；FIFO、C、QEMU 等后端按实现进度接入，范围不同不强行互比。
4. 补实验 00 四类学习任务及作者干净环境记录，安排独立学习者试读并根据卡点修订；未试读时保留待验证，不代填参与者或成绩。

首批交付为契约/资产清单、最小档预算及短跑报告、比较与重放入口、实验 00 教材验收记录。以上工作均待执行；本次仅将步骤纳入规划。完成后按下方主线推进，不等待全部模型语料或 Agent 任务库建成。

先用 G0/G1 的小型同步 FIFO 建立共用设计、验证与重放模板，并行推进 M1 的“4×4 INT8 阵列与 Python 随机对照”，随后再集成 CPU。软件并行实现 AL07 计算图检查、C 整数参考及固定形状 Linear 的计划解释器；按 [单线性层贯通实验](AI_COMPILATION.md) 接 QEMU/RTL，以 G2 报告验收，再扩大到完整 LLM。

首批任务继续包含 FIFO 的 MATH-E1 不变量、固定 GEMM 的 ARCH-E1 字节账本、C 参考的 SW-E1 边界语义与 SW-E5 最小 manifest。本轮新增内容先落实 PERF-E1 的比较输入/计时范围，MEM-E1 的事务轨迹格式和 PPA-E1 的设计范围；Agent 独立从 AGQ-E1 的任务/相关性标注开始。加载器进入 G2 时再接坏包与所有权测试，不一次铺开全部 48 个深化子实验。

推进门槛：图检查和量化参考 → C 计划执行与数值对照 → 设备 GEMM 与分块 → 单线性层端到端报告 → 模型集成。首个演示可使用原创固定权重，不等待完整模型训练；OSTEP 小实验和 LFS 系统扩展按需求并行。首次引入外部项目时固定不可变提交与许可证，每项实现同时补实验正文。

互连扩展的首项工作为 IO01 的地址/握手用例，以及可并行的 NET02 回环消息协议和 NET03 CPU 确定性计算服务；先验证它们，再建立 IO02 的 Linux/EDU 驱动环境。CXL 保留为满足前置条件后的 S3 实验。

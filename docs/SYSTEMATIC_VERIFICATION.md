## 第一组 FIFO 验证用例

采用 DD 文档唯一的 FIFO 契约，不另造更高吞吐的 full/read/write 行为。按以下顺序形成最小证据集：

1. 复位后为空；写满四项；第五次写入未被接收；顺序读回。
2. 空时同时尝试读写，只接受写入；满时同时尝试读写，只接受读出；中间占用时双向传输。
3. 多轮指针回绕、长时间背压、连续吞吐；用已接收序列校验输出顺序与内容。
4. 非空/满/停顿时复位，取消旧数据；复位后重新建立比较基线。
5. 固定随机种子运行，记录每沿信号、占用和第一次失败；缩短失败序列，仍保留原种子与完整日志。
6. 检查关键性质并注入错误变体，证明检查器可以捕获相应错误。形式 proof/cover 与动态测试分别报告。

## 证明边界与工具选择

初期使用现有 Verilator 测试方式与轻量检查器，按需要评估 cocotb；不要求先掌握完整 UVM。形式路线评估 Yosys/SBY 与相应求解器，限定可支持语法、参数及环境。UVM 方法学习可借鉴，但不是引入闭源工具的理由。

每份形式报告必须保存 reset/输入合法性假设、属性、引擎、界限、版本与结果。用可达性检查暴露过强约束和从未触发的断言；证明只适用于当前模型和假设。异步设计的多时钟、同步器延迟和复位假设另写，不能从单时钟 FIFO 证明直接推广。

跨层差分比较“共同承诺的行为”：纯功能模型比较输入输出事务，周期模型按共同采样规则比较事件，QEMU 与 RTL 不要求未经定义的逐周期一致。模型可信度另见 [SIM 课程](SIMULATION_CREDIBILITY.md)。

## 领域 03 与 17 深化：软件正确性与可复现工程

SW-E1–E6 是 DV08 与 CSAPP/运行时中的原创子实验，不新增一级领域或新工具栈。首个对象为宿主 C 整数参考与受限模型包加载器，接入 [AC10](AI_COMPILATION.md) 和 G2。全部待实现；宿主检测工具与裸机/guest 测试分开，未支持的平台不能继承检查结果。

| 子实验 | 知识与前置 | 实验产物 | 验收要求 |
| --- | --- | --- | --- |
| SW-E1 C 数值与内存语义 | CS02/CS03、ENG01；整数提升、溢出、对齐、别名、对象生命周期 | C INT8/GEMM 参考与标量边界用例；以 Python 作独立 oracle | 明确定义模 2^32 累加，不依赖有符号溢出；无越界/未对齐访问/失效指针；设备维度限制另测 |
| SW-E2 模型包与协议校验 | AC10、AL03；长度/偏移、字节序、版本、形状、能力与资源上限 | 固定小格式的合法包及截断、重叠、溢出、未知版本等反例 | 分配/解引用前验证乘加与整段范围；拒绝超预算输入；失败不发布半初始化模型，缓冲区全部回收 |
| SW-E3 自动检测与模糊测试 | DV02/DV07；动态检测、静态分析、覆盖引导、最小复现 | 在支持的宿主构建启用 ASan/UBSan；先定向字节变异，再评估 coverage-guided fuzzing | 人为植入的越界/失效释放/未定义行为被发现；固定执行/内存预算，保存语料与最小失败输入；无报告不等于已证明安全 |
| SW-E4 所有权与错误恢复 | OS04–OS07；申请/提交/完成/取消/释放、错误传播 | 对加载、提交、分配失败与超时注入故障，维护资源账本 | 失败路径无双重释放/泄漏；设备静止或完成前不回收被访问内存；timeout 不等于任务已取消 |
| SW-E5 可复现构建与环境 | Git、构建依赖、编译器/ABI、锁定版本、环境隔离 | 生成实验 manifest，在两个独立构建目录或干净 Linux guest 重建并复现固定输出 | 保存代码/输入/工具/依赖哈希和命令；记录差异；“功能可复现”和“产物逐位相同”分别验收 |
| SW-E6 回归与跨层调试 | DV08、SIM04；接口兼容、请求关联、回归语料、CI | 把合法/非法包和故障轨迹接入分层回归，关联运行时/驱动/设备请求 | 同一失败可定位到层与输入；固定版本旧包按兼容策略接受或拒绝；CI 只标实际跑过的平台 |

SW-E1 的回绕实现优先使用明确的无符号模运算，最后以可表示的宽整数计算对应有符号值，再转换到 INT32；不能依赖超范围无符号转有符号的未说明行为。超大 K 或累加器溢出用例属于参考/算术单元测试，不作为 NPU v0 合法输入。

SW-E2 先限定静态形状、有限张量数和总字节预算，明确偏移重叠/共享常量的政策；格式定版前只使用测试样本。校验和用于发现损坏，不作为来源真实性或授权证明。加载器只解析数据，不接受任意代码反序列化。

SW-E5 的 manifest 至少记录提交、宿主/目标架构与 OS、编译器和 flags、模拟器/库版本、依赖来源与哈希、输入/配置/随机种子、资源上限、执行入口、预期输出与实际日志。先按实验选择最小环境，macOS 宿主、Linux 工具和 RV32/RV64 guest 分开验收；不把完整 LFS 构建设为每次复现的前置。

参考 [AddressSanitizer](https://clang.llvm.org/docs/AddressSanitizer.html)、[UndefinedBehaviorSanitizer](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html)；模糊测试方法与具体引擎在实现时核对维护状态、平台支持与版本。当前未新增检测器、测试语料、构建锁文件或 CI 作业。

## 跨层契约的实施与验收

这是 DV01/DV08、SW-E2/E5/E6 与 AC01–AC11 的共同交付要求，不另增课程编号。以下校验器、适配器与报告均待实现；现有 Python GEMM 和单 MAC 测试不代表跨层契约已经贯通。

| 步骤与阶段 | 实施工作 | 交付物 | 验收标准 |
| --- | --- | --- | --- |
| 1. G0 固定边界 | 列出模型导出→执行计划→运行时→设备的生产者/消费者；把数值、布局、地址、错误与生命周期要求逐项编号，指定唯一规范来源 | 契约登记表、需求—消费端—用例矩阵、版本与兼容策略 | 每条跨层要求有来源和检查位置；未支持能力明确列出；规范冲突先解决，不能由不同后端自行解释 |
| 2. G2 软件先行 | 定义模型包/计划的结构化格式，实现加载前校验；记录张量 dtype/shape/layout、量化参数、偏移/长度、需求能力与设备 ABI 版本 | 格式说明、合法/坏包样例、校验器、后端能力清单 | 未知版本、越界、长度溢出和布局不符在使用数据前拒绝；缺失设备能力时拒绝提交，仅对已通过输入校验且显式允许回退的任务走 CPU，并报告实际路径 |
| 3. G1/G2 接后端 | FIFO 先建立周期观察约定；Linear 的 Python、C/计划、QEMU、RTL 分别实现同一用例的适配器 | 输入/输出与事件适配器、逐后端符合性报告 | 同一资产版本按已声明观察层比较；整数逐元素精确一致，浮点按事先固定的误差阈值；未实现或跳过的后端不能标成通过 |
| 4. G2/G3 持续回归 | 统一运行/用例/节点/分块/事务标识，加入错误变体与版本升级回归 | 首个分歧诊断、失败重放命令、兼容与迁移记录 | 报告首个不一致位置、期望/实际值及规范条款；故意破坏布局、版本或累加规则会使检查失败；升级不静默改写旧期望结果 |

契约分层维护：设备行为以 [NPU v0](../specs/npu-v0.md) 为准，量化/计划以 [AI 编译](AI_COMPILATION.md) 为准，FIFO 采样/复位以 [DD03](DIGITAL_DESIGN_TIMING.md) 为准。结构化格式后续放在既有 `specs/` 下；本轮不修改设备 ABI。模型包格式版本、契约版本和设备 ABI 版本分别记录，不能用一个版本号代替所有兼容判断。能力清单须关联实现提交、平台和用例结果，不能仅凭后端自报就认定支持。

首个贯通对象沿用 G2 的 `Linear M=5,K=257,N=7`：权重由 `W[N,K]` 转为 `B[K,N]`，拆成 K=256 和 K=1 两次合法设备任务，各从零累加；CPU 合并 INT32 部分和后仅应用一次缩放和 bias。逻辑 K 范围使用一致的激活量化尺度。K=257 是编译层分块用例，直接交给 v0 设备则必须拒绝。模型文件保存偏移，运行时绑定并验证 guest 地址；不能把宿主指针写入计划冒充设备地址。

比较报告分开记录量化质量、整数计算、设备协议和性能。QEMU 与 RTL 在共同的命令/结果边界比较，不要求同步回调暴露与 RTL 相同的 BUSY 周期；周期证据另列。参考期望须来自独立算法或手算小例，不能用被测后端产生的输出自行证明正确。共享资产的版本和故障用例按 [共同实验资产](ENGINEERING_BRIDGES.md#共同实验资产的实施与验收) 管理。

## 算术结构与数据完整性的验证接入

[ARITH-E1–E6](DIGITAL_DESIGN_TIMING.md#dd01dd02dd07-深化计算机算术与算术电路结构) 为 DV02/DV06/DV08 增加位宽、符号、进位/溢出、乘积与事务级等价用例；不同延迟的乘法/MAC 先按已接收请求比较，不强求逐周期相等。结构比较的功能证据与综合/STA 分开，定点舍入实验不修改 v0 的 INT32 回绕。

[RAS-E1–E6](ARCHITECTURE.md#领域-04-与-17-深化硬件数据完整性与故障处置) 为 DV01/DV07/DV08 增加故障模型、编解码、保护范围、错误事件和结果有效性验收。注入器与被测编解码逻辑分离，保存码字版本、地址/位掩码、时刻/持续时间、请求/epoch、期望类别和实际处置。分别记录无错误报、已纠正、不可纠正、静默损坏、未完成和范围外故障；缺乏覆盖证据不能由“未见静默错误”推为零风险。

首个 (13,8) 编码实验穷举数据和单/双错误位置，存储/GEMM 系统测试再加入时序、背压、复位与永久故障。二态翻转模型不覆盖全部模拟、电气或未知态故障；复位清状态不等于修复坏存储。软件/RTL 正常输出和错误状态均需独立 oracle；将错误译码器、重复事件计数或 UE 后仍报成功等变体加入回归。全部为待实现安排，沿用四项共同交付机制。

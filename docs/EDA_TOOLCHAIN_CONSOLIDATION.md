# 本地 EDA 工具链统一方案

日期：2026-11-17。适用项目：AIMakeAll 与外部 `~/asic-lab` 芯片实验环境。

状态：**方案文档，尚未实施版本切换或卸载。** 版本与路径依据当天的 [本地环境分析](LOCAL_EDA_ENVIRONMENT.md) 和 [盘点快照](environment/local-eda-2026-11-17.json)。后续执行前需重新盘点，不能把本文当作实时安装状态。

## 1. 结论与目标

现有 Verilator、Yosys、Magic 可以逐步收敛到各自的一套主用版本。建议顺序是 **Yosys → Verilator → Magic**：先统一调用入口，再做兼容性回归，通过后切换，最后清理不再需要的安装。

“统一”分两步完成：

- **使用统一**：项目配置明确选择版本，所有脚本通过相同入口调用，不再依赖偶然的 PATH 顺序。
- **安装收敛**：确认旧版本没有使用者、可以恢复且新版本通过验收后，再移除冗余安装。依赖包管理器保留的历史版本不属于正在使用的第二套环境。

目标是降低维护成本、避免结果来自错误版本，并保持已有实验可复现。此轮不同时升级 PDK、Python、ngspice、OpenRAM 或 UVM，以便定位工具切换引起的变化。

## 2. 当前版本与候选目标

| 工具 | 当前部署 | 统一目标 | 当前判断 |
| --- | --- | --- | --- |
| Yosys | Homebrew 0.60；Nix 0.62，后者配套插件、SBY/EQY | Nix 管理的 0.62 工具组合 | 优先处理；还需验证旧调用方和包依赖 |
| Verilator | Homebrew 5.044；UVM 专用 5.054 | 5.054，保留已验证的 UVM 与 macOS 配置 | 可作为统一候选，需重编译并回归所有消费者 |
| Magic | Nix 8.3.623；RC 提取专用 8.3.703 | 8.3.703 作为候选，兼容性通过后决定 | 暂不能直接替换；涉及 LibreLane 补丁、DRC 和提取结果 |

新版版本号较高并不构成兼容性证据。LibreLane 按特定工具版本构建，替换工具可能影响稳定性与可复现性，因此它内部的依赖也要纳入迁移。[LibreLane 官方说明](https://librelane.readthedocs.io/en/latest/installation/manual_installation/index.html)

## 3. 各工具的合并方案

### 3.1 Yosys：统一为固定的 0.62 工具组合

现有 `verification-env.sh` 已将 Nix 的 Yosys 0.62 放到 PATH 前部，而普通终端仍可能调用 Homebrew 0.60。这是最明确的重复入口。

迁移时将 Yosys、所需插件、SBY、EQY 和求解器作为一个验证组合登记，不能只替换一个 `yosys` 文件。保留对应 Nix 来源和依赖锁；检查 LibreLane 实际使用的综合程序，确认与项目配置一致。

验收内容：APB 综合、形式验证、综合前后等价检查、CDC/RDC 结构检查及 PWM/APB 物理流程。已有正常例应继续通过，注入故障的负例应继续被检出。综合网表文本可能变化，功能是否一致以等价检查为准；面积、时序和警告变化另行记录。

退出条件：所有调用方明确使用目标版本，插件能够加载，必要回归通过；检查没有其他项目或 Homebrew 包依赖旧安装后，才清理 0.60。

### 3.2 Verilator：统一候选为 5.054

5.054 已用于本机 UVM 邮箱实验；5.044 用于 AIMakeAll 的基础 MAC，以及既有数模联合流程。两者尚未完成跨用途替换验证。

迁移工作包括：

1. 保留已固定的 UVM 源码版本和 `macos-dpi.patch`，不同时升级 UVM。
2. 在统一入口中设置匹配的 `VERILATOR_ROOT`、`VERILATOR_BIN`，避免调用器与运行库来自不同安装。
3. 保留无空格路径别名 `~/asic-lab`。当前 UVM 启动器直接使用含空格的真实路径会出现问题。
4. 在新构建目录重新生成 C++ 模型、编译测试台和数模联合动态库，避免复用 5.044 的构建产物。
5. 检查 `examples/mixed_signal/run.py`：它显式清除部分 Verilator 环境变量，并把 5.044 写入报告。迁移后应记录实际调用版本，不能只更改报告字符串。

验收至少覆盖：MAC 全输入对与溢出测试、APB/cocotb、UVM 多种子与负例、覆盖率，以及 ngspice `d_cosim` 的三个正常例和断反馈负例。UVM 通过不能代替数模联合兼容性验证。

退出条件：上述消费者都能用 5.054 重新构建并通过验收，编译警告与输出变化已解释；再切换日常默认并清理 5.044。

### 3.3 Magic：最后统一，先验证 8.3.703

现有 8.3.623 服务于已建立的物理检查流程；8.3.703 被新 SRAM RC 提取脚本显式调用。`openram-env.sh` 和普通器件 SRAM 检查脚本仍引用旧版，因此修改 PATH 不足以完成迁移。

另一个关键依赖是 LibreLane 源码中的 `instance_name_length.patch`。必须确认新版是否已包含等效修复；如未包含，需要适配补丁并验证长实例名场景，不能假定版本升级自动覆盖本地需求。

迁移流程：

1. 固定 Magic 8.3.703 的源码提交、构建参数及必要补丁。
2. 从小型反相器开始，对照旧版的 DRC、严格 LVS、网表连接和 RC 提取结果。
3. 在固定 PDK 下验证 SRAM 位单元、镜像拼接、完整宏，再验证数字 PWM/APB 的物理流程。
4. 修改 LibreLane 对应的 Nix 工具定义，构建独立候选环境，检查实际执行路径；不得覆盖 `/nix/store` 内文件。
5. 对提取差异做电路检查和必要的版图后仿真，确认原有零违规不是因为规则未加载或检查项丢失。

不同版本可能改变网表排序、寄生网络划分或报告格式。不能仅凭文件哈希不同判失败，也不能仅凭 DRC 数量同为零判通过。需核对规则、器件、端口、连接和 RC 参数，解释电路行为上的差异。

如果提取网表发生实质变化，依赖该网表的时序和功耗表征需要重新完成，旧 Liberty 不能自动沿用。如果候选版本暂不能覆盖所有流程，就保留两个明确隔离的配置，直到问题解决。

## 4. 统一入口的设计要求

以下是待实现要求，当前 `make eda-doctor` 仅提供环境盘点功能。

| 要求 | 目的 |
| --- | --- |
| 项目配置集中记录工具路径、预期版本、源码与补丁哈希 | 减少脚本中散落的绝对路径 |
| 分别保留数字、UVM、SRAM 的运行配置 | 共享工具版本，同时隔离 PDK、Python 和实验参数 |
| 每个实验在独立子进程设置环境 | 避免上次实验残留变量改变本次行为 |
| 启动时核验版本和必要插件 | 缺失或不匹配时报错，不能静默退回旧安装 |
| 日志记录实际路径、版本、输入哈希和配置 | 能追溯结果使用了哪套环境 |
| 新旧结果输出到独立目录 | 对照结果并保留回退依据 |

Nix 的依赖路径由构建结果决定；统一用户命令并不自动统一 LibreLane 的内部依赖。完整迁移需同时检查项目脚本、Homebrew 调用和 Nix 依赖闭包。Nix 支持通过工具定义重建定制环境，适合管理这一过程。[官方安装与定制说明](https://librelane.readthedocs.io/en/stable/installation/index.html)

## 5. 实施顺序与验收门槛

| 步骤 | 工作 | 完成标准 |
| --- | --- | --- |
| 0. 固定基线 | 盘点当前工具，保存源码锁、补丁、环境入口和结果 | 能明确重现旧环境；确认长任务使用的配置 |
| 1. 统一入口 | 建立集中配置，迁移路径引用 | 每个调用方实际版本可追踪，找不到目标时明确失败 |
| 2. 切换 Yosys | 使用 0.62 完成综合、形式、等价和物理流程 | 正常例通过、负例检出、差异有解释 |
| 3. 切换 Verilator | 使用 5.054 重新构建基础、UVM 和数模消费者 | 完成对应回归，运行库和生成产物版本一致 |
| 4. 验证 Magic | 用候选环境完成物理及提取对照 | 规则、补丁、连接和电路行为通过；受影响表征重做 |
| 5. 发布新基线 | 更新锁文件、盘点脚本和项目文档 | 所有正式入口使用已验收目标，旧环境仍可恢复 |
| 6. 清理旧安装 | 检查依赖与使用者，通过包管理器清理 | 不破坏其他项目或正在运行的任务，记录实际释放空间 |

清理属于最后一步。Nix 中的历史工具可能仍被其他环境或保留的回退配置引用；需检查引用和垃圾回收根，不手动删除 store 路径。Homebrew 也应先检查已安装包的依赖，避免强制卸载仍被使用的工具。

## 6. 回退与长任务保护

迁移每次只改变一个工具组合；保留原始环境入口、锁文件、源码补丁以及需要恢复的构建配方。候选测试失败时恢复入口配置，用旧环境在独立目录复现，不覆盖原有通过记录。

2026-11-17 的审计快照显示 SRAM RC 表征尚未全部完成。开始迁移前须重新确认任务状态；长任务仍在使用的工具、共享库、路径、PDK 和输出目录保持稳定，候选环境另建。不能仅因进程已启动就认为卸载依赖不会影响后续阶段。

两套 SKY130 继续分别固定：数字流程为 `8afc8346a57fe1ab7934ba5a6056ea8b43078e71`，SRAM 流程为 `e8294524e5f67c533c5d0c3afa0bcc5b2a5fa066`。工艺库统一属于独立迁移任务，需重新核对规则、模型与交付视图。

## 7. 结果记录模板

每个工具切换后，在变更记录中填写：

| 字段 | 要记录的内容 |
| --- | --- |
| 工具身份 | 旧/新版本、实际路径、源码提交、插件和补丁 |
| 实验环境 | PDK、Python、编译器、种子、输入文件哈希 |
| 回归结果 | 命令、退出码、正常例与负例、日志位置 |
| 结果差异 | 功能、覆盖率、物理检查、面积、时序、RC 与警告 |
| 切换判断 | 通过 / 阻塞，原因和未覆盖范围 |
| 回退方式 | 原环境恢复入口及可获得的依赖 |
| 清理结果 | 被移除安装、依赖检查记录、实际释放空间 |

当前完成的是依赖分析、只读盘点工具和本统一方案。版本切换、兼容性回归、统一入口实现及旧安装清理均待执行。

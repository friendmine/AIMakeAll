## 数值与性能怎么衔接

ENG03 的方法基础现在由 [数字设计 DD](DIGITAL_DESIGN_TIMING.md)、[系统化验证 DV](SYSTEMATIC_VERIFICATION.md)、[仿真可信度 SIM](SIMULATION_CREDIBILITY.md) 展开。DD 交付可综合模块和时序约束，DV 提供需求/参考/覆盖/性质/故障证据，SIM 提供模型说明、确定性轨迹、校验及参数敏感性；ENG03 汇总跨层正确性与性能报告，不重复计算课程完成度。

量化模型质量与设备算术正确性分开验证。设备 INT32 回绕是底层语义，模型路径应避免意外溢出；浮点误差不能简单要求所有规模都满足同一个绝对阈值。报告同时给输入分布、dtype、形状、最大误差和约定指标。

性能先测 C 基线，再接设备。记录计算、打包、搬运、轮询/等待、CPU 回退和后处理开销。带宽/峰值计算模型用于解释瓶颈，不能代替实测；首版同步轮询尚不支持把计算与传输重叠当作既成能力。

SoC 验证在单 MAC 之外增加寄存器、总线、复位、驱动和共享内存边界。迁移外部形式验证、等价检查或覆盖率工具时，明确覆盖对象和性质；不将工具安装或外部案例通过当成本项目已通过。

## ENG03 深化：并行计算与性能工程

PERF-E1–E6 归入已有领域 02/03/04/11/18，连接 CS05/CS06/CS12、OS05/OS06、ARCH-E1/E6 和 SW-E1/E5。以下为原创待实现子实验，先在宿主 CPU 开展，保持 Ibex RV32 与 NPU v0 不变；不要求 GPU、集群或新一级目录。

| 子实验 | 知识与前置 | 实验产物 | 验收要求 |
| --- | --- | --- | --- |
| PERF-E1 可比较的基线 | SW-E1/E5、SIM07；测量边界、预热、计时分辨率、工作量 | 固定 GEMM 输入、标量参考、计时入口和原始样本；区分内核与端到端耗时 | 校验输出并防止无用计算被优化掉；输入/布局/精度/线程数一致；计时含不含分配、打包、启动须写明 |
| PERF-E2 局部性与分块 | CS05/CS06、ARCH-E1；循环次序、连续访问、工作集、packing | 比较循环重排、不同 tile 与显式打包，保留访问账本和热点分析 | 每次优化先过数值/尾块测试；打包耗时和额外内存计入端到端；计数器不可用时不能虚构 cache miss |
| PERF-E3 SIMD 与指令级并行 | C 类型/别名/对齐、整数提升、向量尾部、归约 | 先用编译器向量化报告和反汇编，再按支持的宿主 ISA 试一个显式向量内核 | 指令与实际目标匹配；窄乘积先正确扩宽，不混用饱和和回绕；非整向量长度/未对齐输入有明确策略，标量回退另验 |
| PERF-E4 线程并行与同步成本 | OS05/OS06、AL07；任务划分、归约、伪共享、work/span | 按独立输出 tile 分配线程，扫描线程数和粒度，对照串行、单 worker 与多 worker | 无数据竞争；K 并行使用私有部分和再合并；计入启动/同步，报告负载不均和负加速；线程/库并行数避免意外嵌套 |
| PERF-E5 流水与搬运重叠 | DD02、SW-E4、SIM02；有界队列、双缓冲、所有权与依赖 | 先用事件模型比较串行和双缓冲；具备独立生产/计算/消费资源后再做宿主流水 | 缓冲区不提前复用，取消/背压可重放；模型与实现分栏，共享同一带宽时计入竞争，不把 max 时间公式当普遍实测 |
| PERF-E6 多层性能报告 | ARCH-E6、SIM05–SIM07；Roofline、Amdahl、吞吐/尾延迟 | 固定负载对照标量、优化 CPU、guest CPU、QEMU 设备和 RTL，未实现后端留空 | 优化 CPU 基线与教学标量同时保留；算术/质量一致，开销可归因；墙钟、周期、理论上界分别报告，不强求所有优化都更快 |

首个正确性负载复用 AC 的 `M=5, K=257, N=7`，检查设备 K 分块和阵列尾块；该小输入不单独承担吞吐结论。性能另选受宿主内存预算约束的多尺寸固定集合，公开重复次数、计时器、编译选项、目标 ISA、实际线程数和样本。先冻结实现与输入再比较；冷热缓存、调频/后台干扰等条件写入记录，无法控制的因素标为限制。

PERF-E3/E4 的整数参考沿用 SW-E1 的定义明确的模 2^32 语义；浮点重排或 fast-math 需独立精度实验，不能自动沿用原容差。宿主 SIMD 不表示 Ibex 支持向量扩展。优化库若作为对照，须另查实际 dtype/累加语义、线程配置、版本与许可，不能用不同精度结果替代同语义基准。

PERF-E5 是后续并行模型/后端实验：首版 NPU 仍同步轮询、单请求，未实现的 DMA、双缓冲或异步完成不写进 v0 能力。PERF-E6 的算术强度须指定主存/缓存/局部存储边界及 MAC 计数约定，理论峰值、经验带宽和实际达成值分开。

方法入口：[MIT 6.172 性能工程](https://ocw.mit.edu/courses/6-172-performance-engineering-of-software-systems-fall-2018/)、[LLVM 向量化与诊断](https://llvm.org/docs/Vectorizers.html)。仅借鉴方法与组织原创实验，未安装并行库或运行新基准。

## 数据与训练怎么衔接

处理顺序为来源登记 → 文档/任务族去重与划分 → 过滤与分词 → 训练样本 → 模型与指标。近重复数据的规则和人工抽查记录进入数据清单，不能仅靠随机切分窗口。

区分数据重建、训练过程可恢复和权重逐位相同三个目标。跨设备或非确定算子下不能保证后者时，记录容差和评估波动。实验清单统一保存数据/词表哈希、配置、代码版本、优化器状态、检查点和验证指标。

## 检索与状态怎么衔接

先实现小型本地词项索引与 Top-k，配人工标注的问题—相关文档集合；向量检索和重排器放在后续扩展。回答应保留来源引用，检索命中不自动代表回答正确。

检索与决策质量进一步按 [AGQ-E1–E6](../agents/README.md) 展开：任务/相关性标注 → 排序 → 上下文依据 → 工具选择/终止 → 多步计划 → 消融与端到端质量。该组与下方 STATE 的权限/持久恢复共用任务环境，分别报告质量与可靠性，不把一种指标代替另一种。

工具调用区分只读任务和有副作用任务。为请求定义唯一编号、状态转移、超时和重试规则；先用模拟副作用验证重复执行与中断恢复，再接实际工具。模型生成的 observation 不得改变执行权限，越权路径、无效参数和指令注入输入进入回归集合。

## ENG04 深化：持久状态与安全子实验

STATE-E1–E6 归入已有领域 05/12/13，连接 OS09–OS11、NET03–NET05 和 DV08，不新增数据库/安全一级课程。全部待实现；使用本地测试目录、隔离进程/guest 和模拟副作用，不调用真实外部工具。初版可用 Python 标准库接口连接本地 SQLite，实施时记录实际 SQLite 版本和配置。

| 子实验 | 知识与前置 | 实验产物 | 验收要求 |
| --- | --- | --- | --- |
| STATE-E1 信任与权限边界 | OS11、ENG04；身份、授权、数据来源、最小权限与资源预算 | 画请求→校验→工具→状态存储的信任边界，定义工具/目录/资源允许清单 | 未认证/越权/超预算请求有确定错误；模型/检索内容不能改权限；秘密不写入日志 |
| STATE-E2 持久任务状态 | OS06/OS09；状态机、原子提交、请求编号、唯一约束、租约与尝试编号 | 单机任务库与事件轨迹，记录待执行/执行中/成功/失败/结果未知 | 同一身份范围内重复编号/相同内容返回已有状态，不同内容拒绝；状态推进原子，旧尝试不能覆写新结果 |
| STATE-E3 事务与崩溃恢复 | OS09、SW-E4；事务边界、日志/同步、进程与存储故障差异 | 同一数据库事务内执行模拟账本更新与任务完成，提交前后杀进程并恢复查询 | 提交前回滚、提交后结果可查询且重复不再更新账本；固定 journal/synchronous/文件系统假设，杀进程不冒充断电验证 |
| STATE-E4 重试与不确定结果 | OS10、NET04；deadline、取消、幂等键、退避、外部副作用窗口 | 模拟远端“已执行但回复丢失”，实现状态查询/对账及有界重试 | 不能确认结果时保留未知，不盲目重做非幂等操作；记录幂等范围/保留期；超时与取消语义分开 |
| STATE-E5 安全故障回归 | SW-E2/E3、NET04；路径逃逸、符号链接、输入注入、并发权限变化 | 在隔离目录中构造恶意路径/文档/协议与超大任务，验证拒绝和资源限制 | 正常任务可完成；越权路径/工具名被拒绝；避免仅检查路径字符串或仅靠提示词保护，Linux 专用机制另验 |
| STATE-E6 端到端恢复与审计 | DV08、SIM04；重启、并发领取、去重窗口、审计与模型版本 | 规则 Agent→任务库→模拟工具的固定任务集，注入断连/重启，再接模型与推理后端 | 单独报告重复副作用、未知结果、恢复成功、拒绝/超时和任务成功率；日志可关联请求/尝试且不泄漏敏感内容 |

首个贯通实验先做单进程/单机任务队列：请求编号按身份与操作范围唯一，保存请求内容摘要、版本与结果；任务状态和模拟副作用放在同一个事务中提交。之后才加入多 worker 领取与租约，并为每次执行分配尝试编号，旧 worker 的完成必须经过条件更新拒绝。

数据库事务不能原子包住任意外部工具调用。外部副作用与本地记录之间存在不确定窗口时，优先使用外部幂等键/结果查询或对账；缺少这些能力时保留结果未知并要求明确处置，不宣称通用“恰好一次”。租约过期也不能单独阻止旧 worker 继续产生外部副作用，需要工具侧防重/隔离或其他明确协议。

持久化实验使用一次性本地数据库与固定同步设置，不以损坏真实文件测试。记录 `journal_mode`、`synchronous`、运行库版本及文件系统；进程崩溃、OS 崩溃和掉电模型分别标注。SQLite 的原子提交与隔离说明见 [原子提交](https://www.sqlite.org/atomiccommit.html)、[隔离](https://www.sqlite.org/isolation.html)；本课程只验证选定配置与故障模型。

安全检查覆盖输入到执行的整条路径：鉴别请求身份 → 校验参数/预算 → 决策授权 → 受限执行 → 持久结果 → 脱敏审计。身份/密码/TLS 使用标准机制，不自行设计密码算法；用于模型决策的内容不能成为权限配置。先验证规则策略，再替换为模型策略，二者成绩分别记录。

## 资源预算的实施与验收

资源预算贯穿 ENG02/ENG03、ARCH-E1、PERF-E1 和 SW-E5，先保证最小实验能运行，再决定是否扩大规模。下列预算清单与测量报告均待实现；现有 MiniMind 静态估算不能当作本机训练实测。

| 步骤与阶段 | 实施工作 | 交付物 | 验收标准 |
| --- | --- | --- | --- |
| 1. G0 建运行档位 | 只读记录机器/系统/工具与可用资源，定义“最小正确性”“教学训练”“性能与扩展”三档；首批只建立第一档 | 环境快照、运行配置、资源上限表 | 每个准备执行的配置明确内存、磁盘、线程/进程、训练步数或仿真周期和最长运行时间；无依据的数值保留待测，未填实际上限不启动大实验 |
| 2. G2/M3 做静态账本 | 按分配与释放时刻计算同时存活的数据，检查设备地址/对齐与分块容量；训练、推理、仿真分别核算 | 估算公式、张量/缓冲区生命周期表、余量与假设 | 数学尺寸、字节长度和地址计算无溢出；权重、临时区、部分和、KV 或优化器等没有漏项，不能仅用参数量判定能否运行 |
| 3. 各阶段小规模试跑 | 先短训练/小矩阵/有限事务，再测峰值和耗时；记录测量工具、采样间隔、进程范围与单位 | 原始测量、估算—实测对照、异常退出与清理记录 | CPU RSS、设备显存、磁盘和时间按各自口径记录；不支持测量的项写“未测”，不能记零；超限可停止并留下失败记录 |
| 4. 扩规模前决策 | 预先选定安全余量与通过阈值；比较预估、实测和上限，逐次改变 batch/context/规模等一个主要参数 | 继续、缩小或后置的决策表；新配置与复测报告 | 通过必须同时满足正确性与所选档位预算；超预算即使输出正确也不算该档位通过，缩规模后重新验收，不能继承大规模性能结论 |

预算表最小字段为：配置 ID、提交/工具版本、资产 ID/哈希、估算或实测标记、资源项/单位、上限、估值、峰值、余量、测量与停止方法、结果和限制。规划阶段允许上限待定，实际运行前必须填入数值及依据。软件超时/周期上限、系统硬限制与定期采样告警分开描述；仅能采样时不承诺能防止瞬时内存耗尽。不得为跑实验擅自修改整机限制。

| 对象 | 必须核算的范围 | 对应记录位置 |
| --- | --- | --- |
| GEMM/单 Linear | 原始 INT8 A/B 与 INT32 C 的基础字节数 `M*K + K*N + 4*M*N`；另计浮点原件、布局转换、对齐、分块部分和、同时存活的副本及 CPU 回退 | ARCH-E1 / AC08 / PERF-E1 |
| 训练 | 参数、梯度、优化器状态、激活、数据批次、保存/恢复的磁盘峰值；混合精度主副本若存在也计入 | ENG02 / 模型训练配置 |
| 推理/Agent | 权重、激活、KV cache、暂存区、索引/上下文、请求并发、工具调用次数与超时 | 运行时 / AGQ-E6 / STATE-E1 |
| 仿真/构建 | guest 代码/栈/堆与设备缓冲区；宿主 QEMU/RTL 构建和运行开销、波形与日志大小 | SW-E5 / SIM / 实验运行记录 |

上述基础字节公式不是峰值内存公式。每份报告分别列宿主墙钟、guest 时间、RTL 周期和建模估值；不从 QEMU 墙钟推算芯片频率、硬件加速比或功耗。PPA 延续原有库、活动和设计范围要求，资源预算不替代功耗测量。

## 算术与硬件故障实验的共同交付

[ARITH](DIGITAL_DESIGN_TIMING.md#dd01dd02dd07-深化计算机算术与算术电路结构) 与 [RAS](ARCHITECTURE.md#领域-04-与-17-深化硬件数据完整性与故障处置) 复用以上机制，不另建一级资产库。数值资产增加位宽/进位、符号极值、定点舍入和点积序列；故障资产增加原始码字、故障掩码、注入位置/时刻/持续时间、地址/请求/epoch、保护范围与预期 CE/UE/无错类别。正常控制组、范围外故障和错误实现变体均保留，期望不能只由被测编解码器产生。

资源账本新增乘法器状态/流水寄存器、校验位、修复写回流量、事件日志和故障运行次数；区分数学可算的位数开销、逻辑综合资源和实测周期。实验前限定穷举/抽样规模与日志上限，故障覆盖分母不能只包含被检测事件。教材迁移任务分别要求解释“结构变化为何不改变整数结果”及“哪些错误在保护范围外”；真实学习者记录仍待开展。当前均为规划，没有新增硬件能力或故障覆盖成绩。

## 与推进顺序的关系

1. 先将 ENG01/ENG03 接入 [单线性层贯通实验](AI_COMPILATION.md)，并行推进 4×4 阵列。
2. 开始预训练前完成 ENG02 的小数据流水线；训练恢复与模型评估必须有独立记录。
3. 开始 Agent 集成时完成 ENG04，再扩展持久状态和并发；不以模型能输出工具 JSON 代替任务验收。

分布式训练、多 GPU、生产级集群、完整数据库、芯片制造和封装测试保留为长期扩展，尚未建立系统课程。基础语法和数学按实验需要补齐。

# AI 编译 从模型计算图到 NPU 执行

更新：2026-11-17。目标是把模型表示、数值语义和硬件接口连接成可检查的执行计划。**当前仅完成课程与方案设计，尚无编译器、导出器或计划执行器实现。** 首版自写小型转换器；[MLIR Toy 教程](https://mlir.llvm.org/docs/Tutorials/Toy/)作为后续框架参考，不增加当前必装依赖。

## 1. 首版范围与职责

从固定形状的单个 `Linear` 开始，随后扩展到小 MLP，再到自写 Transformer 的线性层。输入是项目定义的有限计算图和权重，不默认支持任意 PyTorch 程序、动态图、ONNX 或完整 MiniMind 自动导出。

编译阶段决定形状、布局、量化策略、分块、缓冲区需求及执行顺序；运行时负责加载、地址绑定、动态输入处理、任务提交和错误处理；驱动负责设备协议。静态编译可以生成运行期激活量化步骤，不必把每个输入的量化值预先固定。

```mermaid
flowchart LR
    MODEL[有限计算图与权重] --> CHECK[形状、类型与依赖检查]
    CHECK --> LOWER[布局转换与量化策略]
    LOWER --> TILE[GEMM 分块与 CPU 回退]
    TILE --> MEMORY[生命周期与缓冲区规划]
    MEMORY --> PLAN[执行计划与模型包]
    PLAN --> RT[C 运行时与驱动]
    RT --> BACKEND[CPU / QEMU / RTL 对照]
```

## 2. 知识与实验模块

`AC01–AC12` 为项目编号。实验均为原创设计；MLIR 概念用于对照，不表示相应功能已引入。

| 模块 | 学习重点 | 项目实验 | 验收标准 |
| --- | --- | --- | --- |
| AC01 | 编译阶段、前端/中端/后端、AST 与 IR | 定义有限图的输入、输出、常量和操作 | 对每个被支持的操作给出语义；未知操作明确拒绝或使用已定义回退 |
| AC02 | 符号、DAG、use-def、拓扑排序及诊断 | 用 AL04/AL07 检查图并生成确定性顺序 | 缺输入、环、重名、非法属性均定位到节点；共享权重不误复制 |
| AC03 | 张量形状、dtype、布局、stride 与广播 | 检查 `Linear` 输入权重输出的维度 | 不匹配维度、零/负尺寸及大小溢出被拒绝；不隐式接受不支持的 stride |
| AC04 | 图变换、常量处理、死节点与融合条件 | 删除未使用常量，比较变换前后图 | 依赖与副作用不丢失；浮点重排需单独数值验证；融合不虚构设备能力 |
| AC05 | 降级、布局转换、算子合法化与回退 | 将 `Linear` 分为 GEMM、缩放和 bias | NPU 只接支持的整数 GEMM；CPU 回退被列入计划和耗时统计 |
| AC06 | 校准、量化类型、scale 作用域、舍入与饱和 | 浮点线性层到对称 INT8，记录逐通道权重 scale | 约定全零、异常数、舍入与溢出策略；校准集与测试集分离 |
| AC07 | 循环、tiling、尾块、重用和归约 | 对超过设备维度的 GEMM 生成分块任务 | 覆盖 M/N/K 尾块；重复执行确定；K 部分结果合并正确 |
| AC08 | 内存生命周期、别名、对齐与 bufferization | 为计划分配静态 arena，先不复用再做复用 | 活跃张量不重叠；容量不足明确失败；计划地址为偏移，由运行时绑定 |
| AC09 | 调度、成本模型、带宽与计算瓶颈 | 比较简单分块/调度方案的搬运量和执行次数 | 估算与测量分开；首版同步轮询不能假设存在搬运计算重叠 |
| AC10 | 计划编码、版本、模型包与后端 ABI | 输出可检查计划，由 C 解释执行或生成 C 调用 | schema、常量哈希、能力要求完整；加载器拒绝畸形长度、未知版本 |
| AC11 | 差分验证、阶段定位和性能回归 | 浮点 → 量化参考 → 计划解释器 → C → QEMU/RTL | 整数内核逐元素一致；浮点后处理有明确容差；质量和速度分别验收 |
| AC12 | MLIR dialect、pass、lowering、代码生成 | 用 Toy 学习框架后，再评估接自定义 NPU 后端 | 记录固定版本与环境；Toy 的 LLVM 输出成功不代表 NPU 已接通 |

## 3. 与 NPU v0 的具体契约

以 [现有规范](../specs/npu-v0.md) 为唯一设备语义基准，编译实验不暗中修改寄存器或算术定义。

- **布局**：模型权重通常保存为 `W[N,K]`，设备输入 B 为连续行优先 `B[K,N]`；转换器负责转置/打包。A、B 都必须满足设备布局，切片不连续时要复制到连续缓冲区。
- **算术**：设备只做 INT8×INT8→INT32，每条命令从零开始，不支持旧 C 累加、bias、scale 或非线性。bias 和反量化先放 CPU。
- **分块**：每条命令 M/N/K 均不超过 256；4×4 阵列是拟实现的内部微结构，不能据此将设备最大矩阵维度误设为 4。尾块的填充与掩码由所选实现明确。
- **K 归约**：多个 K tile 的 INT32 结果需要在 CPU/运行时合并，不向设备发送未经定义的累加命令。正常模型路径先检查总归约溢出风险；验证回绕语义时使用有定义的模运算，不能借用 C 有符号溢出。
- **量化尺度**：首版在一个逻辑 GEMM 的 K 归约范围内保持激活 scale 一致，权重可逐输出通道缩放。不同尺度的部分结果不能直接整数相加；更复杂的分组量化需额外定义与验证。
- **协议**：首版同步提交、轮询完成、CLEAR 后提交下一任务；不假定中断、异步 DMA、cache coherence 或任意重叠执行已经存在。
- **地址**：文件中存放逻辑缓冲区偏移及长度，不固化宿主指针。运行时绑定 guest 物理地址并检查 32 位寄存器范围；RV64 Linux 的驱动与地址能力另行适配。

## 4. 第一个贯通实验

建议使用原创的固定形状 `Linear`，例如 `M=5, K=257, N=7`：既跨越 K=256 设备边界，又覆盖未来 4×4 阵列的尾块。该形状是拟定用例，尚未运行。

1. 保存浮点输入、权重与 bias，计算参考输出。
2. 固定量化规则，生成 INT8 输入/权重及 scale，计算整数参考。
3. 建图、检查、转布局并生成 K=256 和 K=1 两个部分任务；必要的连续打包显式列出。
4. 在纯软件计划解释器中执行、合并部分和，最后反量化并加一次 bias。
5. 复用计划接 C 标量后端；设备实现完成后再接 QEMU 与 RTL。
6. 报告整数一致性、浮点误差、设备调用次数、搬运字节和峰值缓冲区；性能仅在对应后端真实执行后记录。

随后推进两层 MLP、Transformer 单层线性路径与完整模型。硬件阵列可以并行开发，完整 LFS 和完整 MLIR 构建都不阻塞最初的软件实验。

## 5. 执行计划应包含的内容

计划格式仍待实现阶段定版，至少描述：格式版本、目标能力、输入/输出张量、dtype/形状/布局、量化规则、常量偏移与哈希、缓冲区容量/对齐/生命周期、操作序列、后端与回退、错误规则。设备基址和实际内存地址由运行环境决定。

先采用容易检查的计划和解释执行；等语义稳定再优化编码或生成代码。新增字段与 [运行时方案](../runtime/README.md) 一起审查，未知能力不得静默降级成看似成功的结果。

## 6. 互连与异构内存的后续连接

[PCIe IO05](PCIE_IO_FOUNDATIONS.md) 为计划增加新的设备能力目标，但 BAR、DMA 地址和完成通知由驱动与运行时处理；不把具体地址固化进模型包。[CXL CX05](CXL_MEMORY_FOUNDATIONS.md) 可利用 AC08 的生命周期信息形成内存类别提示，运行时另验实际放置、可寻址范围和暂存成本。[网络 NET03–NET05](NETWORKING_FOUNDATIONS.md) 在服务层传输请求与结果，首版不把远程 RPC 自动当作可任意切分的图算子。这些属于待实现扩展，不改变首个单 Linear 实验范围。

## 7. 框架阅读与来源

- [MLIR Toy](https://mlir.llvm.org/docs/Tutorials/Toy/)：从 AST、IR 和变换到逐级降级、LLVM 代码生成，再到类型扩展。作为概念与框架学习，不声称提供本项目硬件后端。
- [MLIR Bufferization](https://mlir.llvm.org/docs/Bufferization/)：阅读张量语义如何映射到内存缓冲区，以及复用时的别名和读写约束。
- [MLIR Quantization](https://mlir.llvm.org/docs/Quantization/)：对照量化值、scale、zero point 和表示转换；本项目仍采用 NPU v0 支持的子集。

编译原理基础按需补符号、类型、控制/数据流与优化合法性，不要求先实现通用语言编译器。实际引入 LLVM/MLIR 时另锁提交、构建配置与适用许可证；当前只新增原创设计和官方链接，未安装、运行或复制上游实现。

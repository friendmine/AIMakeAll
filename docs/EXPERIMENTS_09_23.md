## 复现环境

在仓库根目录运行。已有完整环境时，可直接按编号串行验收。

```sh
make -j1 labs09-23
```

单项入口为 `make lab09` 至 `make lab23`。训练检查点由 make 根据源文件和语料生成，完整环境包含以下依赖。模型和 RTL 默认均在宿主 CPU 上运行。本次全套在 macOS arm64 完成。

| 实验 | 需准备的环境与资产 |
| --- | --- |
| 09、12–20 | Python 3.11.7、CPU 版 PyTorch 2.14.1、Make、C/C++ 编译器与 Verilator 5.044；09、17–20 另需可生成 RV32IM/ILP32 的 GCC 15.1.0、binutils、Newlib/libm。13 只需 Verilator 与 C++。16 的计时发生在宿主；其 make 前置会用到 15 的 RTL。 |
| 10、11 | Python 和 CPU 版 PyTorch，语料与许可已随仓库提供。重建两种宽度各需 1,600 个训练步。 |
| 14 | Yosys 0.60、OpenSTA 2.7.0、SKY130 HD 标准单元库 `sky130_fd_sc_hd__tt_025C_1v80.lib`。用环境变量 `AIM_LIBERTY` 指向库、`STA` 指向可执行文件。报告保留库摘要和时序约束。 |
| 17 | 先按[项目版 QEMU 构建说明](../simulator/qemu-v0/README.md)准备带教学 MMIO 设备的 RISC-V QEMU 9.2.4。环境变量/Make 参数 `LINEAR_QEMU` 可选择其路径。 |
| 21、22、23 | 沿用 15 的模型包。准备 QEMU 9.2.4 源树（默认沿用项目版源码，或设置 `QEMU_SOURCE`），以及该版 QEMU 的构建依赖、Meson、Ninja。`make course-linux-qemu` 在 build 下单独构建 x86 系统模拟器和 PCIe 端点。 |
| 21、22 | Go（本机 1.25.6）交叉编译静态客体程序，Alpine Linux 6.12.115-0-virt x86_64 内核。22 的跨机用例另需同版启动镜像中的 e1000 模块。首次运行从 [Alpine 3.22.8 固定版本目录](https://dl-cdn.alpinelinux.org/alpine/v3.22/releases/x86_64/netboot-3.22.8/) 下载并校验 SHA-256。离线复现时可通过 `AIM_LINUX_KERNEL`、`AIM_LINUX_INITRAMFS` 指向已保存的匹配版本。23 使用 qtest，可单独运行。 |

**第一次复现可先跑** `make lab10` 看语料和训练曲线，然后运行 `make lab12` 看相同张量如何进入电路。只想检查模型与固件能否对齐时，运行 `make lab17`。各目录内的 `verified-run.json` 保存本机验收样本，新运行写入 `build/`；其中的大文件、波形、编译产物和可重建的检查点由读者按需生成。

## 如何读各类数字

- 实验 09、17–20 的“整机拍数”来自运行客体固件的 PicoRV32 RTL。09 的完整请求含模型包校验；17–20 使用已链接进映像的模型。只在同一实验的对照组间计算加速比。
- 实验 12、14 给出阵列本身的周期；14 的面积和时序为映射网表结果。实验 13 是独立共享请求队列验证。
- 实验 16 的宿主时间、实验 20 的工具执行时间与模型周期分别记录。实验 21、22 报告 Linux 客体单调钟测得的纳秒；两台客体间无需同步时钟，往返在客户端测量，服务内各阶段在服务端测量。
- 实验 23 从 QEMU 的实际 Type 3 地址窗口读写权重及 KV，算术由宿主执行。字节数来自实际执行的放置策略；按 8 / 16 / 32 GB/s 折算的时间仅给出固定带宽下的搬运下界。

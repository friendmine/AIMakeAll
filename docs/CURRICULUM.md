# 课程目录

面向会基础 Python、C 数组与指针，并愿意动手推导矩阵运算的个人学习者。由[实验 00](../labs/00-int8-matmul/README.md)入门，用[实验 01](../labs/01-linear257/README.md)贯通第一个算子。随后依次验收电路、检查点、推理后端和跨层设计决定。[三项能力与个人毕业任务](CHIP_MODEL_PLAN.md#个人毕业任务)

课程统一采用 [仿真优先与数字电路交付原则](SIMULATION_FIRST.md)：硬件实验做 RTL/波形/综合，系统实验做 QEMU/Linux/虚拟网络。板卡、PHY 电气验证和流片不列入核心验收。网络补 NET-H1–H3 数字数据路径，PCIe IO06 改为事务级/RTL 仿真，CXL 补 CX-H1/H2 子模块与一致性模型，均待实现。

## 芯片与 AI 全景补全课程

[十条补全路线](CHIP_AI_COMPLETENESS.md) 覆盖十个全景缺口，按全景通识、核心实践、专题深入组织。SIG/CIR 建立数学信号到器件电路的连续课程；HET/CHIP 补 CPU/GPU/DSP 与产品流程；CLA/EMB/SCALE 补经典 AI、感知控制及规模工程。PRA/DEP/DLE 将既有数字设计、部署与 UDL 课程整理成实现和比较门槛。

每条路线三个验收节点，共 30 个，DEP 已在单层用例取得部分验收证据；节点会复用 DD/DV/SIM、AC、UDL 等已有实验，不作为 30 个额外独立实验累加。详细前置、原理序列、产物、数值/故障验收、仿真边界和资源档位在链接文档中统一维护。课程先完成 PRA 的 FIFO 与 DEP 的单 Linear，DLE 小模型并行；其他路线不全部前置于主线，编号 01–18 与一级目录不变。

新章节仍须按下文模板逐章编写并通过作者复现/独立学习者验证；已运行的对象单列于总表；当前状态以本页总表为准。

## 教材学习者验证的实施与验收

教材交付分为“作者复现”“自动化检查”“独立学习者验证”，每项绑定章节版本、路线和环境，互不替代。新增机制先试点 [实验 00](../labs/00-int8-matmul/README.md)，再进入 FIFO、单 Linear、训练与 Agent 章节；当前尚无独立学习者试读记录。四项共同交付安排见 [整体里程碑](ROADMAP.md#四项共同交付的阶段安排)。

| 步骤与阶段 | 实施工作 | 交付物 | 验收标准 |
| --- | --- | --- | --- |
| 1. M0 定义学习任务 | 说明目标读者与必要前置，区分 Python 基础路线和需要 Verilator 的 RTL 路线；给出预计资源/时间及依据 | 章节任务单、环境/依赖清单、预期中间结果与评分规则 | 不依赖作者私有路径或隐藏文件；每个学习目标有可观察任务；未测耗时标待测，不伪造学习时长 |
| 2. 作者从干净环境复现 | 从指定提交和显式依赖开始，只按正文执行，收集失败与修复步骤 | 完整命令、结果、实际耗时/峰值资源、常见错误说明 | 声明路线的命令和中间结果可复现；缺依赖有明确诊断；缺 RTL 工具时只能标 Python 路线通过 |
| 3. 独立学习者试读 | 至少一名符合目标前置、非本章作者的学习者从新检出开始，完成运行、解释、迁移和排错任务 | 脱敏试读记录：前置/环境、耗时、卡点、提示、任务结果 | 四类任务均按预先规则通过；完成不依赖正文外的阻断性提示。需要额外帮助的步骤记录问题，修订后复测，不抹去首次失败 |
| 4. 修订与发布 | 将卡点转为教材改动/待办，复测受影响步骤；标明只验证过的读者与平台范围 | 修订差异、复测结果、章节验收状态 | 阻断问题已解决并复测，方可标该版本/路线“学习者验证通过”；单人试点不代表所有初学者或所有平台均可完成 |

每章在原写作模板中补充：目标读者与前置自检、预算档位、资产/契约版本、关键中间结果、分层提示、学习任务评分和验收状态。记录使用匿名参与者编号，不收集无关个人信息；AI 模拟试读或自动脚本只能算辅助检查，不能作为独立真人学习者证据。尚未组织试读时可以推进实现与作者复现，但保持“学习者验证待执行”。纯规划文档更新不以完成真人试读为前置。

实验 00 的首轮任务与评分规则：

| 任务 | 学习者应交付 | 通过条件 |
| --- | --- | --- |
| 运行 | 按正文得到固定矩阵结果与测试输出 | 与正文一致，能指出 Python GEMM 与 RTL MAC 各自验证的范围 |
